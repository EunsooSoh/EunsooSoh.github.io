## Abstract & Introduction
* Flash memory 특징:
    * 장점(HDD 대비)
        * 비휘발성(non-volatility)
        * 빠른 접근 속도
        * 충격 저항성(shock resistance): HDD는 자기 디스크가 회전하고 그 위를 헤드가 움직이며 데이터를 읽고 쓰는 기계적 구조라서, 충격이나 진동을 받으면 헤드가 디스크 표면에 부딪혀 손상되거나 데이터가 유실될 위험이 큼. 반면 플래시 메모리는 이런 움직이는 기계 부품이 전혀 없는 solid-state -> 떨어뜨리거나 흔들리는 등의 물리적 충격에도 훨씬 안정적으로 동작.
        * 저전력 소비
        => 모바일 기기에 많이 사용됨
    * 단점
        * erase-before-write(쓰기 전에 지움)
            * erase-before-write: 메모리의 한 위치를 갱신하려면 새 데이터를 쓰기 전에 반드시 그 위치를 먼저 지워야 함. 
            * erase 단위의 크기 != read, write 단위의 크기 -> 전체 시스템 성능 저하가 발생.
        => FTL(Flash Translation Layer) 필요함
* FTL
    * logical-to-physical address mapping table(논리-물리 주소 매핑 테이블)
        * 물리 주소 위치에 이전에 쓰인 데이터가 있으면 
            1. 입력 데이터를 empty physical location(아직 데이터가 쓰이지 않은 곳)에 쓰고
            2. 매핑 데이블에 새로운 논리, 물리 주소 매핑 추가
            => overwrite 연산 때문에 block 하나가 바로 erase 되는 것을 방지 -> erase를 최대한 미룸
* 임베디드 어플리케이션에 FTL 알고리즘 적용할 때 고려 사항2
    1. storage performance
        * 전체 시스템 성능은 주로 쓰기 성능에 영향을 받음
        * erase 비용이 write/read 비용보다 훨씬 크기 때문에 erase 연산을 최소화 해야 함
    2. RAM 요구량
        * FTL에서 갖는 매핑 정보를 유지하기 위한 RAM 메모리
        * RAM 요구량 증가 -> cost 증가 
본 논문에서는 SOTA FTL SW, 문제 정의 알고리즘과 이슈를 다룸. 

## 2. 문제 정의 및 FTL 기능
### 2.1 문제 정의
**def 1**. sector: 한 번에 읽거나 쓰는 데이터의 최소량. 즉 read, write 연산의 단위.
**def 2**. block: erase 연산의 단위. block 크기는 sector 크기의 배수

![Fig. 1 전체 flash file system 구조](/assets/img/posts/FTL/image.png)
* 구조: Applications(응용 PGM) -> File System(file system API 사용) -> FTL(Flash Translation Layer, 논리 sector 번호로 I/O) -> Flash Memory(플래시 메모리, physical sector 번호로 I/O)

* file system 계층: 
    1. logical sector number를 포함한 read 또는 write 명령을 내려 특정 주소의 데이터를 읽거나 씀.
    2. 1에서 얻은 logical sector number는 FTL의 mapping algorithm에 의해 실제 physical sector number로 변환
* FTL 문제 정의: 
    * 플래시 메모리가 n개의 physical sectors로 구성된다고 가정.
    * 상위 계층인 파일시스템은 플래시 메모리를 m개의 logical sectors로 구성된 block-I/O 장치로 간주.
    * 하나의 logical sector는 적어도 하나의 physical sector에 매핑되어야 하므로, m <= n.

**def 3**. 
    * flash memory는 다수의 blocks으로 구성되며, 각 block은 다수의 sectors로 구성. 
    * flash memory 특성: flash memory 내의 physical sector 위치에 이미 데이터가 쓰여 있는 상태에서 새 데이터가 기존 데이터를 덮어쓰려면 반드시 block 단위로 지워져야 함. FTL 알고리즘은 파일시스템이 준 logical sector 번호로부터 flash memory 내의 physical sector number를 산출함.
=> 덮어쓰려면 지워야 하는데, flash 특성 상 무조건 sector보다 더 큰 단위인 block단위로 erase해야 함. 근데 erase 비용이 reade나 write하는 비용보다 커서 최소화해야 함.

### 2.2 FTL 기능
FTL 알고리즘은 아래 세 가지 기능을 제공해야 함.
* Logical-to-physical address mapping: FTL 알고리즘의 주요 기능, 파일시스템의 논리 주소를 flash memory의 물리 주소로 변환하는 것.
* 전원 차단 복구(Power-off recovery): FTL 연산 도중 sudden power-off event이 발생하더라도, FTL 자료구조가 보존되고 data consistency이 보장되어야 함.
    * data consistency: 매핑 테이블(논리-물리 주소 매핑 정보)과 실제로 플래시 메모리에 저장된 데이터가 항상 서로 정확히 대응됨. 
    ex. 매핑 테이블은 갱신됐는데 실제 데이터는 옛날 값이거나 그 반대 -> data consistency를 보장하지 않는다고 함.
* Wear-leveling: 메모리 block들이 최대한 고르게 쓰이도록 하는 기능.
    * 특정 block에만 쓰기/erase가 반복되면 그 block만 빨리 마모되어 수명이 짧아짐 ->  사용을 분산시켜 전체 수명을 늘림
