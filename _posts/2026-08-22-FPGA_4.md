* PS(Processing System): 
    - CPU 코어와 주변 장치
    - 순차적 처리
    - 유연하고 복잡한 논리 제어에 유리

* PL(Programmable Logic):
    - FPGA 하드웨어 영역
    - Verilog나 VHDL 같은 HDL로 원하는 디지털 회로를 직접 설계
    - 대규모 병렬 처리

=> Zynq SoC: 칩 하나에 PS, PL 두고 사이에 AXI 인터페이스 뚫어서 통신

## 1. AXI 인터페이스

ARM 사에서 만든 칩 내부 통신 표준 규격(AMBA).

* AXI4-Lite
    - 가장 가볍고 단순. 
    - 한 번에 주소 하나, 데이터 하나(보통 32비트)만 딱 주고받음.
    - PS가 PL에게 간단한 명령을 내리거나, 작업 상태를 확인할 때 씀. 
    - 대량의 데이터 전송에는 부적합.


* AXI4 (Full AXI)
    - 대용량 데이터를 한 번에 실어 나르기 위한 방식. 
    - 주소를 한 번만 알려주면 그 뒤로 연속된 데이터를 이어서 보낼 수 있음.
    - DDR에 있는 데이터 덩어리를 PL로 가져오거나 그 반대로 보낼 때 사용.


* AXI4-Stream
    - '주소' 개념이 아예 없음.
    - 그냥 시작부터 끝까지 데이터를 쏟아냄. -> 병목X, 속도 제일 빠름.
    - 카메라 영상 데이터, 오디오 신호처럼 순서대로 끊임없이 들어오는 실시간 데이터를 처리할 때 씀.

## 2. 대규모 데이터 운송 시스템

PS(CPU) 대신 데이터를 옮겨주는 것

* DMA (Direct Memory Access)
    - CPU를 거치지 않고, DDR과 PL 사이에서 직접 데이터를 퍼 나르는 독립적인 하드웨어 블록.
    - PS가 DMA에게 어떤 주소에서부터 몇 개의 데이터를 보내라고 지시만 해두면, DMA가 알아서 AXI4 타고 데이터 다 옮긴 뒤 interrupt.


* Descriptor
    - DMA가 한 번에 여러 개의 복잡한 작업을 해야 할 때(Scatter-Gather 방식) 읽어보는 것. => 이게 있어서 CPU 개입 없이 메모리 전송 작업 가능
        - Scatter-Gather 방식: CPU가 여러 개의 작업 지시(Descriptor)를 미리 메모리에 연속해서 적어두고, DMA가 그걸 스스로 읽어가며 꼬리물기식으로 알아서 흩어져(Scatter) 있는 데이터를 모아(Gather) 전송
    - 구성
        - Source Address: 원본 데이터가 있는 메모리 시작 주소
        - Destination Address: 데이터를 보낼 목적지 주소
        - Length (Bytes): 전송할 데이터의 총 길이
        - Next Descriptor Pointer: 지금 작업이 끝나면 다음에 읽어봐야 할 다음 Descriptor의 메모리 주소
        - Control/Status: 이 작업이 끝났는지, 에러가 났는지 등을 표시하는 상태 비트

## 3. 소프트웨어와 하드웨어의 약속

* Register ABI (Application Binary Interface)
    - PS가 PL을 제어하려면 특정 메모리 주소(Register)에 값을 써넣어야 함. 이때 "몇 번지 주소가 무슨 기능을 하는가"를 미리 맞춰둔 약속.
