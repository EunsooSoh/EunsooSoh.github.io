## 1. 하드웨어 연산의 기본 단위

* MAC (Multiply-Accumulate)
    - '곱셈(Multiply)'과 '누산(Accumulate, 덧셈)'을 한 번의 클럭 사이클에 동시에 처리하는 연산 유닛.
    - 행렬 곱셈($Y = W \times X + B$)은 데이터를 곱한 뒤 그 결과를 계속 더해나가는 과정 -> 하드웨어 설계 시 곱셈기와 덧셈기를 하나로 묶어 이 과정을 한 번에 처리하도록 만든 것.
    - 하드웨어 가속기의 성능(ex. 연산 속도)을 결정하는 가장 핵심적인 부품.


* PE (Processing Element)
    - 하드웨어 가속기 내부에서 독립적으로 데이터를 처리할 수 있는 가장 작은 기본 연산 블록.
    - 하나의 PE 안에는 보통 1개 또는 여러 개의 MAC 유닛과 계산 중간 값을 임시로 저장하는 레지스터, 그리고 제어 로직이 포함됨.

## 2. 연산 속도 최적화 기법

* 파이프라이닝 (Pipelining)
    - 하나의 데이터 처리 과정을 여러 개의 작은 단계로 쪼갠 뒤, 하드웨어들이 쉬지 않고 겹쳐서 실행하도록 만드는 설계 기법 => 속도 극대화.
    - 데이터 읽기 -> 곱셈 -> 덧셈 -> 저장의 4단계가 있을 때, 1번 데이터가 곱셈 단계로 넘어가면 2번 데이터가 즉시 읽기 단계로.


* Reduction Tree (덧셈 트리)
    - 여러 개의 값을 모두 더해야 할 때 순차적으로 더하지 않고, 트리 구조로 짝을 지어 병렬로 더하는 하드웨어 구조.
    - ex. 8개의 숫자를 1열로 차례대로 더하면 총 7번의 클럭이 필요 -> 2개씩 짝지어 더하면 (8개 -> 4개 -> 2개 -> 1개) 단 3번의 클럭만에 계산이 끝.

## 3. 성능 평가 및 분석 지표

* Throughput vs Latency
    - Throughput (처리량)
        - 시스템이 단위 시간당 처리할 수 있는 총 데이터의 양. (ex. 1초당 처리하는 이미지 장수, 초당 처리 바이트 수). 
        - 병렬 처리와 파이프라이닝을 통해 값을 높일 수 있음.
    - Latency (지연 시간)
        - 데이터 하나가 시스템에 입력된 순간부터 최종 결과가 출력될 때까지 걸리는 시간.
        - 자율주행이나 실시간 제어처럼 즉각적인 반응이 필요한 시스템에서는 처리량보다 지연 시간을 줄이는 것이 중요.


* Roofline Model
    - 설계한 가속기나 AI 알고리즘의 성능 병목 원인을 분석하기 위해 사용하는 2차원 그래프 모델.
    - X축은 연산 집약도(데이터 1바이트를 메모리에서 가져올 때 연산을 몇 번 하는지)
    - Y축은 성능(초당 연산 처리량)
    - 현재 시스템의 성능이 최대치에 도달하지 못하는 이유가 '메모리 대역폭이 부족해서(Memory-bound)'인지, 아니면 '하드웨어의 연산기가 부족해서(Compute-bound)'인지 직관적으로 파악 가능 -> 구조 최적화의 방향을 결정에 쓰임.
