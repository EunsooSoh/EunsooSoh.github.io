## 내용 정리

---

**1. 인터넷의 기본 개념과 구조 (The Internet Overview)**

- **인터넷의 구성 요소:** 인터넷은 라우터와 다양한 통신 링크(광섬유, 구리선, 라디오, 위성 등)로 연결된 수십억 개의 컴퓨팅 장치(호스트 또는 종단 시스템)로 이루어진 **"네트워크들의 네트워크"**
- **서비스 관점:** 인터넷은 웹, 비디오 스트리밍, 이메일 등의 분산 애플리케이션에 통신 서비스를 제공하는 **인프라**이며, 애플리케이션들이 인터넷 전송 서비스에 접속할 수 있도록 프로그래밍 인터페이스를 제공
- **네트워크 가장자리 (Network Edge):** 인터넷의 끝단에는 클라이언트와 서버 역할을 하는 호스트들이 위치, 서버들은 주로 데이터 센터에 모여 있음. 호스트들은 유무선 통신 링크를 통해 **가장자리 라우터**에 연결
- **접속 네트워크 (Access Networks):**
    - **케이블 기반 네트워크 (HFC):** 케이블과 광섬유망을 통해 가정들을 ISP 라우터에 연결, 이웃들이 케이블 헤드엔드로 향하는 네트워크를 공유(Shared)하는 비대칭 속도의 통신망
    - **디지털 가입자 회선 (DSL):** 기존 전화선을 활용해 중앙국의 DSLAM에 연결, 음성과 데이터가 다른 주파수 대역을 사용하여 전용선(Dedicated)으로 전송

**2. 네트워크 코어 (Network Core)**
상호 연결된 라우터들의 거대한 그물망(Mesh) 구조

- **Packet Switching:** 애플리케이션 계층의 메시지를 패킷(Packet)이라는 작은 단위로 쪼개어 전송. 라우터는 들어온 패킷을 적절한 출력 링크로 내보내는 지역적 기능인 **포워딩(Forwarding)**과, 출발지에서 목적지까지의 전체 경로를 결정하는 전역적 기능인 **라우팅(Routing)**을 수행. 자원을 공유하므로 **간헐적인(Bursty) 데이터 전송에 매우 효율적**
- **Circuit Switching:** 통신(Call)을 위해 미리 경로 상의 자원을 예약하고 할당(⇒ 지연 시간 예측 가능)하는 방식. 주파수 대역을 나누는 **FDM**이나 시간을 쪼개는 **TDM** 방식을 사용
- **비교 예시:** 1Gbps 링크에서 10%의 시간만 활동(100Mbps 요구)하는 사용자들이 있을 때, 회선 교환 방식은 최대 10명만 수용 가능하지만, 패킷 교환 방식은 35명의 사용자를 수용하더라도 10명 이상이 동시에 활동할(혼잡이 발생할) 확률이 0.0004 미만으로 매우 낮아 효율적

**3. 네트워크 성능: 지연, 손실, 처리율 (Delay, Loss, Throughput)**

- **패킷 지연(Delay)의 4가지 요소:** 전체 노드 지연($d_{nodal}$)은 다음 네 가지 시간의 합
    1. **처리 지연 ($d_{proc}$):** 라우터가 비트 오류를 확인하고 출력 링크를 결정하는 데 걸리는 시간 (수 마이크로초 이하)
    2. **큐잉 지연 ($d_{queue}$):** 링크로 들어오는 비트의 도착률(Arrival rate)이 출력 링크의 전송 속도를 초과할 때, 패킷이 전송되기 전 버퍼에서 대기하는 시간. **트래픽 강도($La/R$**)가 1에 가까워질수록 큐잉 지연은 기하급수적으로 증가
    3. **전송 지연 ($d_{trans}$):** 패킷의 모든 비트($L$)를 링크 대역폭($R$)의 속도로 밀어내는 데 걸리는 시간 ($L/R$)
    4. **전파 지연 ($d_{prop}$):** 비트가 물리적 매체를 타고 다음 라우터까지 물리적으로 이동하는 데 걸리는 시간 ($d/s$)
- **패킷 손실 (Packet Loss):** 대기열(버퍼)의 용량은 유한하므로, **버퍼가 가득 찬 상태에서 패킷이 도착하면 해당 패킷은 버려지며(Drop) 손실 발생**
- **처리율 (Throughput):** 송신자에서 수신자로 비트가 전송되는 속도, 통신 경로 상에서 가장 대역폭이 작은 **병목 링크(Bottleneck link**)에 의해 전체 종단 간 처리율이 결정

**4. 프로토콜 계층과 캡슐화 (Protocol Layers and Encapsulation)**
복잡한 네트워크 시스템을 모듈화하여 설계하고 관리하기 위해 **계층(Layer)** 구조를 사용. 계층 구조는 시스템의 유지보수와 업데이트를 쉽게 해주며, 특정 계층의 내부 구현이 바뀌어도 다른 계층에는 투명하게(영향을 주지 않고) 작동

- **인터넷 프로토콜 스택 (5계층):**
    1. **Application layer:** 네트워크 애플리케이션 지원 (HTTP, SMTP, DNS)
    2. **Transport layer:** 프로세스 간의 데이터 전송 (TCP, UDP)
    3. **Network layer:** 출발지에서 목적지로 데이터그램 라우팅 (IP)
    4. **링크 계층:** 인접한 네트워크 요소 간 데이터 전송 (Ethernet, WiFi)
    5. **물리 계층:** 선로 상의 비트 전송
- **캡슐화 (Encapsulation):** 송신 측에서 데이터가 아래 계층으로 내려가면서, 각 계층의 고유 헤더를 덧붙이는 과정. 애플리케이션 **메시지(Message)**에 전송 계층 헤더($H_t$)가 붙어 **세그먼트(Segment**)가 되고, 네트워크 계층 헤더($H_n$)가 붙어 **데이터그램(Datagram)**이 되며, 마지막으로 링크 계층 헤더(**$H_l$**)가 추가되어 **프레임(Frame)** 단위로 전송
