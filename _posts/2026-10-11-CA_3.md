* **명령어 집합**: 컴퓨터가 이해하고 실행할 수 있는 기계어 명령어의 전체 목록

### 1. RISC-V 하드웨어 설계 원칙 4

1. <span class="hl-yellow">**간단하기 위해서는 규칙적인 것이 좋다**</span> **(Simplicity favors regularity)**
    * 하드웨어 구현을 단순, 비용↓

2. **작을수록 더 빠르다 (Smaller is faster)**
    * 메인 메모리는 수백만 개의 주소를 가지지만, CPU 내부의 범용 **레지스터는 32개**
        * 아래 표는 참고만

    | 레지스터 | 역할 |
    | --- | --- |
    | x0 | 상수 0 |
    | x1 | 반환 주소 |
    | x2 | 스택 포인터 |
    | x3 | 전역 포인터 |
    | x4 | 스레드 포인터 |
    | **x5-x7, x28-31** | **임시 레지스터** |
    | x8 | 프레임 포인터 |
    | **x9, x18-27** | **저장 레지스터** |
    | x10-x11 | 함수 인수 및 반환값 |
    | x12-x17 | 함수 인수 |

3. **좋은 설계에는 적절한 절충이 필요하다 (Good design demands good compromises)**
    * 모든 명령어를 **32비트 고정 길이**로 유지하기 위해 명령어 형식(R, I, S-Type)을 분리하되, 각 형식의 필드 위치를 최대한 동일하게 유지하게

4. **자주 발생하는 경우를 빠르게 처리하기 (Make the common case fast)**
    * 프로그램에서 자주 사용되는 작은 상수는 메모리에서 읽어오지 않고 명령어 자체에 포함(Immediate / 상수 피연산자) → 더 빨리 처리

### 2. 메모리와 레지스터 비교

|  | 레지스터 | 메인 메모리 |
| --- | --- | --- |
| 속도 | 매우 빠름 | 느림 |
| 용량 | 32개(매우 작음) | 매우 큼 |
| 용량 최적화 | 자주 쓰는 변수 우선 배치 | 레지스터 부족해지면 자주 사용되지 않는 변수만 메모리로 쫓아냄(Spill) |


### 3. 피연산자(Operands)의 3가지 종류

1. 레지스터 피연산자
    * 참고) 64비트 = **Doubleword**, 32비트 = **Word**

2. 메모리 피연산자
    * 복합 데이터(ex. 배열, 구조체)를 메인 메모리에 저장
    * 연산 시 아래 과정이 필요
        * 메모리 값을 레지스터로 읽어오고(ld)
        * 레지스터의 결과를 메모리에 저장(sd)
    * 바이트 단위 주소 지정
    * **Little Endian** 방식 (최하위 바이트가 가장 낮은 주소에 위치)
        * 돈이랑 반대로 생각하면 됨

            cf. 빅엔디안: 1250원 1이 최상위

        * ex. 0x12345678

            12 \| 34 \| 56 \| 78로 나눠짐 → 이걸 78부터 저장하는 게 리틀 엔디안(뒷쪽부터 확인이 가능하다)

        * 가장 낮은 거에서부터 처리하면 carry bit 처리가 훨씬 수월함
    * <span class="hl-yellow">C언어 변환 예제</span>

        ```nasm
        ;A[12] = h + A[8];
        ;h는 x21, A시작주소는 x22에

        ld x9, 64(x22) ;x22로부터 64만큼의 offset이 필요함. 8bytes니까
        ; 로드는  <- 이 방향
        add x9, x21, x9
        sd x9, 96(x22) ;96 = 8 * 12
        ; 저장은 -> 이 방향
        ```

3. 상수 피연산자
    * 명령어에 직접 지정된 상수 값 → 메모리 읽기(`ld`) 과정이 없어 연산 속도 향상
    * 종류
        * 부호X: n비트 주어지면 0 ~ 2^n-1까지
        * 부호O: n비트 주어지면 -2^(n-1)~2^(n-1)-1 (n-1인 이유는 부호 표시를 위해 1비트를 부호에 줌)
            * 같은 비트로 표현할 수 있는 양수 개수 ≠ 음수 개수(비대칭성)
            * ex.
                * 가장 작은 음수 10000..0000
                * 가장 큰 양수 011111…1111
                * -1: 다 1
            * <span class="hl-yellow">부호 바꾸기</span>: 보수 취하고 1더하기
            * ⇒ 이렇게 해서 뺄셈기 없이 뺄셈 가능(덧셈기로만 가능하니까) → 단순한 설계 원칙과 연관
    * **부호 확장 (Sign Extension)**: 12비트 상수를 64비트로 확장 시 부호 비트를 복사
        * 양수는 앞을 0으로 채우고
        * 음수는 앞을 1로 채움
        * `lb` : 부호 비트 복사 → 부호 유지
        * `lbu` : 무조건 앞을 0으로 채움(부호 없는 데이터 처리할 때)

### 4. 명령어의 표현 및 기계어 인코딩 (Instruction Encoding)

모든 RISC-V 명령어는 32비트 이진수(기계어)로 변환되어 메모리에 저장·실행됩니다 (Stored-Program Concept).

1. **R-형식 (R-type: Register Format)**: **피연산자가 레지스터**
    * **필드 구성**:

        ![R-형식 필드 구성: funct7(7), rs2(5), rs1(5), funct3(3), rd(5), opcode(7)](/assets/img/posts/CA_3/image.png){: .s70 }

    * `opcode`: 연산 종류, `rd`: 목적지 레지스터, `rs1/rs2`: 소스 레지스터, `funct3/funct7`: 세부 연산 구분.
    * ex.

        ![add x9, x20, x21을 R-형식 필드와 이진수로 인코딩한 예](/assets/img/posts/CA_3/image-1.png){: .s70 }

2. **I-형식 (I-type: Immediate Format)**: 상수 산술 연산 및 로드(Load) 명령어
    * **필드 구성**:

        ![I-형식 필드 구성: immediate(12), rs1(5), funct3(3), rd(5), opcode(7)](/assets/img/posts/CA_3/image-2.png){: .s70 }

3. **S-형식 (S-type: Store Format)**: 메모리 저장(Store) 명령어
    * **필드 구성**:

        ![S-형식 필드 구성: imm[11:5](7), rs2(5), rs1(5), funct3(3), imm[4:0](5), opcode(7)](/assets/img/posts/CA_3/image-3.png){: .s70 }

    * `rs1`과 `rs2` 레지스터 필드의 위치를 R-형식과 일치시키기 위해 상수(Immediate) 영역을 둘로 나눔
    * store방식이기 때문에 rd가 없음(메모리에 저장하기 때문에 목적지 reg가 필요 없음)

### 5. 비트 조작 연산

1. 이동 연산

    비트들을 왼쪽이나 오른쪽으로 밀어주는 연산

    | 명령어 | 명칭 및 비트 채우기 방식 | 구체적 동작 및 효과 | 실전 활용 예시 |
    | --- | --- | --- | --- |
    | **`slli`** / `sll` | **논리 왼쪽 시프트** <br/>빈자리를 **`0`**으로 채움 | 비트를 왼쪽으로 i칸 이동<br/>**2^i를 곱한 효과** | 배열 주소 계산<br/>`A[i]` 접근 시 인덱스 `i`에 8을 곱하기 위해 3비트 좌측 이동 (`slli x10, x22, 3`) |
    | **`srli`** / `srl` | **논리 오른쪽 시프트** 빈자리를 **`0`**으로 채움 | 비트를 오른쪽으로 i칸 이동<br/>부호 없는 정수의 **2^i 나눗셈 효과** | 데이터의 상위 비트를 하위로 내려서 추출할 때 사용 |
    | **`srai`** / `sra` | **산술 오른쪽 시프트**<br/>빈자리를 부호 비트로 채움 | 비트를 오른쪽으로 i칸 이동<br/>부호 있는 정수의 **2^i 나눗셈 효과** | 음수인 거 유지하면서 2로 나누고자 할 때 사용 |

2. 논리 연산 (Logical Operations)

    데이터의 특정 비트를 추출하거나 수정할 때

    * **`and`** / **`andi`** **(AND 연산 & 마스킹)**:
        * **마스킹(Masking)**: 원하는 부분만 1로 and해서 그대로 남김
    * **`or`** / **`ori`** **(OR 연산 & 비트 설정)**:
        * 마스크 1 → 강제로 1로 설정
        * 마스크 0 → 그대로
    * **`xor`** / **`xori`** **(XOR 연산 & 비트 반전)**:
        * 두 비트가 서로 다를 때만 `1`
            * 마스크 1 → 비트 반점
            * 마스크 0 → 그대로
        * NOT 연산 구현: 별도의 `not` 명령어 대신, 전체가 `1`인 값과 XOR 연산(`xori rd, rs, -1`)을 수행
