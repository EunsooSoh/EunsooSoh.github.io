### 1. 동기화 및 원자적 연산

* **데이터 경합 (Data Race)**: 둘 이상의 프로세서가 동일한 메모리 위치에 접근하여 최소 하나가 쓰기연산 수행 시, 접근 순서에 따라 결과가 달라지는 현상
* **HW로 원자적 연산** 지원
* **RISC-V 동기화 명령어 쌍 (`lr.d` / `sc.d`)**
    * **`lr.d rd, (rs1)` (Load Reserved / 예약 로드)**: `rs1` 메모리 주소의 값을 `rd`로 읽어옴 & 해당 주소에 하드웨어적 예약을 설정
    * **`sc.d rd, (rs1), rs2` (Store Conditional / 조건부 스토어)**: `lr.d` 실행 이후 해당 위치의 값이
        * 변경되지 않았다면 `rs2` 값을 (rs1)에 저장 & `rd`에 `0` (성공)을 반환
        * 변경되었다면(다른 프로세서에 의해) 저장 취소 & `rd`에 `0`이 아닌 값 (실패)을 반환
* **핵심 구현 패턴**
    * **원자적 Swap**: x23 ↔ (x20) (주의: x20 자체는 안 바뀜)

        ```nasm
        again: lr.d x10, (x20)      ;1. x20이 가리키는 곳에 있는 값(x20)을 x10에 로드
               sc.d x11, (x20), x23 ;2. x23의 값을 (x20)에 조건부 저장 시도
               bne x11, x0, again   ;3. x11 != 0 (저장 실패) -> again으로
               addi x23, x10, 0     ;4. 저장 성공
               ;지금 x10에 (x20)있으니까 그 값이 x23으로 들어감
        ```

        스토어 실패하면 성공할 때까지 루프를 반복

    * **Lock 획득**: `lr.d`로 락 변수를 읽어 `0`(해제 상태)인지 확인한 후, `sc.d`로 `1`(락 설정)을 쓰는 연산을 성공할 때까지 반복

        ```nasm
        addi x12, x0, 1        ;1. 락을 잠그기 위한 상수 값 1을 x12에 준비
        again: lr.d x10, (x20) ;2. 락 변수 메모리 (x20)의 현재 상태를 읽어 x10에 로드 및 x20에 있는 주소 예약 설정
               bne  x10, x0, again    ;3. x10 != 0 (다른 프로세서가 락을 쥐고 있음)이면 락이 풀릴 때까지 again
               sc.d x11, (x20), x12   ;4. 락이 풀렸으므로, (x20)에 x12에 있는 1을 써서 락 점유 시도
               bne  x11, x0, again    ;5. 락 다시 검사 후 다른 프로세서가 잡았으면 again하든지 끝
        ```

    * **Lock 해제**:

        `sd x0, 0(x20)` : 락 변수에 `0`을 저장하여 해제

### 2. 프로그램의 변환 및 실행 과정

고수준 언어로 작성된 프로그램이 메모리에 로드되어 실행되기까지의 전체 파이프라인

**C 소스 코드** → **컴파일러** → **어셈블리 코드** → **어셈블러** → **오브젝트 모듈** → **링커** → **실행 파일** → **로더** → **메모리 탑재**

1. 어셈블러가 생성하는 객체 모듈 구성요소 6
    1. **헤더 (Header)**: 모듈의 크기 및 세그먼트 위치 등 전체 구조 요약 정보
    2. **텍스트 세그먼트 (Text Segment)**: 번역된 기계어 코드 영역
    3. **정적 데이터 세그먼트 (Static Data Segment)**: 프로그램 실행 전체 동안 유지되는 전역/정적 변수 데이터
    4. **재배치 정보 (Relocation Information)**: 프로그램이 메모리에 로드되는 절대 위치에 따라 수정되어야 하는 주소 정보
    5. **심볼 테이블 (Symbol Table)**: 전역 변수/함수의 정의 및 외부 참조 테이블
    6. **디버그 정보 (Debug Information)**: 소스 코드 라인과 기계어 주소를 연결하기 위한 디버깅용 정보

2. 링커 (Linker-객체 모듈 연결)
    * 개별적으로 컴파일된 오브젝트 모듈들 + 라이브러리 루틴들 결합
        * 세그먼트를 병합
        * 라벨(주소)을 해결
        * 외부 참조 주소를 최종 결정

        ⇒ 하나의 통합된 실행 파일 이미지 생성

    * 재배치 로더가 수정하도록 위치 의존성을 남겨둘 수 있음(가상 메모리 쓰면 재배치 로더가 수정할 일X)

3. 로더 (Loader)
    * 메모리 로드 6단계
        1. 디스크의 실행 파일을 메인 메모리에 올리고 실행을 시작
        2. 가상 주소 공간 생성
        3. 텍스트/데이터 세그먼트를 메모리로 복사
        4. 스택 매개변수 설정(매개변수 있을 때만)
        5. 레지스터(`sp`, `fp`, `gp...`)초기화
        6. `main` 함수(시작 루틴)로 점프

4. 동적 링크 & 지연 링크
    * **동적 링크** (Dynamic Linking): 라이브러리 코드를 실행 파일에 직접 포함X, 실행 시점이나 함수 호출 시점에 필요한 라이브러리만 메모리에 로드/링크

        ⇒

        * 실행 파일 크기 너무 커지는 것 방지
        * 라이브러리 자동 업데이트를 가능

    * **지연 링크 (Lazy Linking)**: 스텁과 간접 참조 테이블을 활용하여, 실제 함수가 **첫 번째로 호출되는 순간**에만 동적 링커/로더를 불러 주소를 연결 → 이후 호출부터는 직접 연결된 주소로 실행
        * 첫 호출: 간접 테이블 → 동적 링커 호출 → DLL 적재 & (호출하려는 함수의) 실제 주소 기록 → 함수 수행
            * DLL: Dynamic Link Library(동적 연결 라이브러리)
        * 재호출: 간접 테이블 → 함수 수행

### 3. 자바(Java) 프로그램 실행 메커니즘 (cf. C)

* **Java Bytecode**: 자바 가상 머신(JVM) 전용 명령어 집합인 바이트코드(`.class`)를 생성
* **JVM 인터프리터 & JIT 컴파일러**:
    * JVM이 바이트코드를 하나씩 Interpret해서 실행

↔ C는 그냥 네이티브 컴파일 → 성능 ↑

### 4. C 정렬 프로그램 종합 구현 예제 (Bubble Sort)

1. `swap` 프로시저 (말단/Leaf 프로시저)

    * **기능**: 배열의 두 요소 `v[k]`와 `v[k+1]`의 값을 바꿈

        ```c
        void swap (long long int v[], long long int k) {
            long long int temp;
            temp = v[k];
            v[k] = v[k + 1];
            v[k + 1] = temp;
        }
        ```

    * **레지스터 매핑**:
        * 배열 시작 주소 `v`: `x10`
        * 인덱스 `k`: `x11`
        * 지역 변수 `temp`: `x5`

        ```nasm
        swap:
            ; 1. [바이트 오프셋 계산] 64비트(8바이트) 정수이므로 인덱스 k에 8을 곱함 (k * 8)
            slli x6, x11, 3       ; x6 = x11 << 3 (k * 8 오프셋)

            ; 2. [실제 메모리 주소 계산] v의 시작 주소 + 오프셋
            add  x6, x10, x6      ; x6 = x10(v) + x6(k*8) -> v[k]의 주소

            ; 3. [메모리 값 로드] 배열 요소 두 개를 레지스터로 읽어옴
            ld   x5, 0(x6)        ; x5 (temp) = v[k]
            ld   x7, 8(x6)        ; x7 = v[k + 1] (8바이트 뒤의 값)

            ; 4. [교환 저장] 두 값을 서로 반대 위치 메모리에 저장
            sd   x7, 0(x6)        ; v[k] 위치에 x7 값 저장
            sd   x5, 8(x6)        ; v[k + 1] 위치에 x5(temp) 값 저장

            ; 5. [복귀] 호출자(sort)에게 돌아감
            jalr x0, 0(x1)        ; x1(ra) 레지스터에 저장된 주소로 복귀 점프, 다음 문장은 버림
        ```

2. `sort` 프로시저 (비말단/Non-Leaf 프로시저)

    * **기능**: 중첩 루프를 통해 `swap` 함수를 지속적으로 호출하며 버블 정렬 수행

        ```c
        void sort (long long int v[], size_t n) {
            size_t i, j;
            for (i = 0; i < n; i += 1) {
                for (j = i - 1; j >= 0 && v[j] > v[j + 1]; j -= 1) {
                    swap(v, j);
                }
            }
        }
        ```

    * **레지스터 매핑**:
        * 배열 시작 주소 `v`: `x10`
        * 배열 크기 `n`: `x11`
        * 외부 루프 인덱스 `i`: `x19`
        * 내부 루프 인덱스 `j`: `x20`
        * 임시 파라미터 보관: `x21`, `x22`

        ```nasm
        ; 1. 스택 프레임 확보, 레지스터 보존
        sort:
            addi sp, sp, -40      ; 레지스터 5개(8바이트 x 5 = 40바이트) 저장을 위해 스택 확장
            sd   x1, 32(sp)       ; x1 (ra, 복귀 주소) 스택 보존
            sd   x22, 24(sp)      ; x22 (s6, 파라미터 n 백업용) 스택 보존
            sd   x21, 16(sp)      ; x21 (s5, 파라미터 v 백업용) 스택 보존
            sd   x20, 8(sp)       ; x20 (s4, 변수 j) 스택 보존
            sd   x19, 0(sp)       ; x19 (s3, 변수 i) 스택 보존


        ; 2. [Outer Loop] 외부 루프: for (i = 0; i < n; i += 1)

            li   x19, 0           ; i = 0 (인덱스 i 초기화)

        for1tst:
            bge  x19, x11, exit1  ; 만약 i >= n 이면 정렬 완료 -> exit1로 이동

        ; 3. [Inner Loop] 내부 루프: for (j = i - 1; j >= 0 && v[j] > v[j+1]; j -= 1)

            addi x20, x19, -1     ; j = i - 1 (인덱스 j 초기화)

        for2tst:
            blt  x20, x0, exit2   ; 만약 j < 0 이면 내부 루프 탈출 -> exit2로 이동

            ; v[j]와 v[j+1]의 주소 계산 및 로드
            slli x5, x20, 3       ; x5 = j * 8 (바이트 오프셋 계산)
            add  x5, x10, x5      ; x5 = v + (j * 8) -> v[j]의 메모리 주소
            ld   x6, 0(x5)        ; x6 = v[j]
            ld   x7, 8(x5)        ; x7 = v[j + 1]

            ble  x6, x7, exit2    ; 만약 v[j] <= v[j+1] 이면 정렬된 상태이므로 루프 탈출

        ; 4. [Procedure Call] swap(v, j) 호출 준비 및 실행

            mv   x21, x10         ; 기존 파라미터 v(x10)를 x21에 안전하게 백업
            mv   x22, x11         ; 기존 파라미터 n(x11)을 x22에 안전하게 백업

            mv   x10, x21         ; swap의 1번째 인자: v (x10 = v)
            mv   x11, x20         ; swap의 2번째 인자: j (x11 = j)
            jal  x1, swap         ; swap(v, j) 함수 호출! (x1에 복귀 주소 저장)

        ; 5. [Inner Loop Repeat] 내부 루프 증감 및 반복

            addi x20, x20, -1     ; j -= 1
            j    for2tst          ; 내부 루프 조건 검사로 이동

        exit2:

        ; 6. [Outer Loop Repeat] 외부 루프 증감 및 반복

            addi x19, x19, 1      ; i += 1
            j    for1tst          ; 외부 루프 조건 검사로 이동

        ; 7. 레지스터 복원 및 스택 해제

        exit1:
            ld   x19, 0(sp)       ; 스택에서 x19 복원
            ld   x20, 8(sp)       ; 스택에서 x20 복원
            ld   x21, 16(sp)      ; 스택에서 x21 복원
            ld   x22, 24(sp)      ; 스택에서 x22 복원
            ld   x1, 32(sp)       ; 스택에서 x1 (ra, 복귀 주소) 복원
            addi sp, sp, 40       ; 스택 포인터 40바이트 해제

            jalr x0, 0(x1)        ; sort를 호출했던 메인 프로그램으로 복귀
        ```

### 5. 배열 vs 포인터

* 배열 vs 포인터 접근 비교:
    * 배열 접근은 루프 내부에서 인덱스 `i`에 대한 주소 계산(시프트 연산 `slli`)이 계속 포함
    * 포인터 직접 증가 방식이 이론적으로 연산을 줄일 수 있음
    * but, 현대 컴파일러는 유도 변수 제거 기법을 통해 배열 코드도 포인터 수준으로 자동 최적화

### 6. 다른 ISA와의 비교 및 RISC-V 확장 아키텍처

1. MIPS 및 x86(IA-32) 비교

    * **MIPS**: MIPS는 `slt`로 0/1을 설정한 뒤 `beq`/`bne`를 조합
    * **x86 (IA-32)**: 가변 길이, but RISC 스타일로 고속 실행

2. 기타 주요 RISC-V 명령어

    * **`auipc rd, immed` (Add Upper Immediate to PC)**: `rd = PC + (imm << 12)`를 수행하며, 뒤이어 `jalr`과 조합하여 PC-상대 32비트 장거리 점프(Long Jump)를 수행할 때 사용
    * **`slt`**, **`sltu`**, **`slti`**, **`sltui`**: 미만(Less Than) 비교 설정 명령어
    * `addw`, `subw`, `sllw`, `srlw`, `sraw` : 32비트 워드를 처리
    * **`RV32I`**: 레지스터 폭과 데이터 경로가 32비트인 변형 아키텍처

3. RISC-V 모듈형 명령어 확장

    블록처럼 쌓아서 조합하는구나 정도만 알아두기

    | 모듈 기호 | 명칭 및 주요 기능 |
    | --- | --- |
    | **M** | 정수 곱셈, 나눗셈, 나머지 연산 |
    | **A** | 원자적 메모리 연산 |
    | **F** | 단정밀도 부동소수점 연산 확장 |
    | **D** | 배정밀도 부동소수점 연산 확장 |
    | **C** | 자주 사용되는 명령어를 위한 16비트 압축 인코딩 확장 |
