1. 보안
- 목표: 조직에서 허가한 사용자만 DB에 접근
- 유형
    
    (1) 물리적 환경에 대한 보호
    
    : 자연 재해와 같은 DB에 가해지는 물리적 위험으로부터의 보호
    
    (2) 권한 관리를 통한 보호
    
    : 권한이 없는 사용자로부터 보호 ⇒ 권한이 있는 사용자만 로그인할 수 있게 제한
    
    (3) 운영 관리를 통한 보호
    
    : 권한이 있는 사람이 제약 조건을 위반하지 않게 통제
    

1. 권한 관리
    
    접근 제어: 권한이 있는 사용자만 DB에 접근할 수 있게 하고, 권한이 있는 사용자도 DB 사용 범위 제한
    
    - 사용자 계정 관리: DBA가 수행
    - 객체: 객체 생성자만 사용 권한이 있음
    
    —(DBA)가—
    
    (1) 시스템 권한 부여
    
    ```sql
    GRANT 시스템권한(DDL) TO 사용자;
    ```
    
    (2) 시스템 권한 취소
    
    ```sql
    REVOKE 시스템권한 FROM 사용자;
    ```
    
    —(객체 소유자)가—
    
    (3) 객체 권한 부여
    
    ```sql
    GRANT 권한[(특정 속성)] ON 객체 TO 사용자
    [WITH GRANT OPTION]; # 사용자 자리에 PUBLIC쓰면 모든 사용자에게 
    ```
    
    - WITH GRANT OPTION: 이 옵션을 추가해야만 이 권한을 받은 사용자가 다른 사용자에게 동일 권한 부여 가능
    
    (4) 객체 권한 취소
    
    ```sql
    REVOKE 권한 ON 객체 FROM 사용자 CASCADE\|RESTRICT;
    ```
    
    *** 권한 취소는 사용자로부터(FROM) 그리고 객체 권한은 사용자 뒤에 여러 개가 붙음
    
    **** 부여: GRANT 권한 ON 객체 TO 사용자 [WITH GRANT OPTION];
    
    **** 취소: REVOKE 권한 ON 객체 FROM 사용자 CASCADE\|RESTRICT;
    
2. 역할
    
    : 일괄적으로 권한을 부여하고 취소할 때 사용
    
    —(2) 역할에 권한 부여를 제외하고는 다 DBA가. (2)는 객체 생성자(=객체 소유자)가
    
    (1) 역할 생성
    
    ```sql
    CREATE ROLE 롤이름;
    ```
    
    (2) 역할에 권한 부여
    
    ```sql
    GRANT 권한 ON 객체 TO 롤이름;
    ```
    
    (3) 사용자에게 역할 부여
    
    ```sql
    GRANT 롤이름 TO 사용자;
    ```
    
    (4) (사용자로부터) 역할 취소
    
    ```sql
    REVOKE 롤이름 FROM 사용자;
    ```
    
    (5) 역할 제거 (이 역할을 부여받은 모든 사용자로부터 이 역할에 부여되어 있던 권한 취소)
    
    ```sql
    DROP ROLE 롤이름;
    ```
