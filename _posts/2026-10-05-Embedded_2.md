### 1-2 핵심
센싱 → 판단 → 제어 루프에서 이 '판단' => **MCU**가.


## 1. 컴퓨터에서 MCU로 (올인원 칩의 구조)

* (복습) - 명령어 실행 구조: Fetch -> Decode -> Execute

### 1) MCU vs MPU 직관적 비교
컴퓨터의 3대 요소 (CPU(연산), 메모리(저장), I/O(입출력))가 칩 레벨에서 어떻게 배치되는지에 따라 구분

* MCU (Microcontroller Unit): CPU + 메모리 + 주변장치(Peripherals)를 단 하나의 칩에 통합
    * Peripherals: CPU, 메모리 제외하고 바깥 세상과 입출력, 시간, 통신 담당하는 HW블록
    ![MCU](/assets/img/posts/Embedded_2/mcu.png){: .s40 }

* MPU (Microprocessor Unit): CPU 단독 칩이며, RAM, SSD, 컨트롤러 등은 바깥에 별도 칩으로 연결하는 고성능 프로세서
    ![MPU](/assets/img/posts/Embedded_2/mpu.png){: .s40 }

| 비교 항목 | MCU (마이크로컨트롤러) | MPU (마이크로프로세서) |
| --- | --- | --- |
| 칩 구조 | CPU + 메모리 + 주변장치 내장 통합 | CPU만 존재 (메모리/I/O 외장 연결) |
| 메모리 규모 | KB ~ MB 단위 (Flash / SRAM) | GB 단위 (외장 DRAM / SSD) |
| 클럭 / 전력 | 매우 낮음 (mW 수준) | 높음 (수 W ~ 수백 W) |
| OS 환경 | Bare-metal (OS 없음) 또는 RTOS | Linux, Windows 등 대형 OS |


#### 2) 주변장치(Peripherals)와 메모리 최적화
* 임베디드 메모리: SRAM(main memory용도), Flash(코드/상수 저장), EEPROM(설정값 저장)으로 나뉘며, 용량이 제한적이라 메모리 최적화가 필수적입니다. (실습 보드 STM32F407: Flash 1MB, SRAM 192KB)
* 전용 하드웨어(Co-processor)의 분업: 전력 효율과 실시간성을 지키기 위해 특수 연산은 전용 하드웨어(DSP: 신호 처리, FPGA: 회로 레벨 병렬 처리, NPU: AI 추론)에 맡깁니다.

### Part 2. MCU 생태계 (ISA와 ARM 표준)

* processor: ISA에 정의된 명령어들을 읽고 해석하여 실행하는 HW
-> 이걸 물리적으로 구현한 게 chip

#### 1) <span class="hl-yellow">ISA와 마이크로아키텍처</span>
* ISA: 
    * Instruction Set Architecture
    * 프로세서가 실행 가능한 명령어 집합에 대한 약속(인터페이스)
* 구현의 분리: Intel과 AMD는 내부 구조(마이크로아키텍처)가 다르지만 동일한 x86-64 ISA 약속을 지키므로 같은 프로그램이 동작.
* MCU 적용: ARM Cortex-M4라는 동일한 ISA -> 제조사가 달라도 같은 코드가 동일 동작.

#### 2) ARM의 IP 라이선스 및 라인업
* IP: 설계, 검증된 회로 설계도(설계 자산)
ARM은 칩을 직접 만들지 않고 설계도(IP)만 판매
* Cortex-A: 애플리케이션 프로세서 (MPU용 — 스마트폰, 라즈베리파이)
* Cortex-R: 실시간 프로세서 (자동차, 산업 제어)
* Cortex-M: 마이크로컨트롤러 전용 (MCU용 — 센서, 모터 제어, IoT) *(수업 실습 보드 mCube-M4가 Cortex-M4 기반)*

### Part 3. IoT와 CPS

#### 1) IoT와 CPS의 차이
* IoT (사물인터넷): MCU + 무선 통신 ➔ 센서 데이터를 수집하여 클라우드/플랫폼으로 전송.
* CPS: 
    * Cyber-Physical Systems
    * 물리 세계(센서·액추에이터)와 사이버 세계(계산·SW)가 실시간 양방향 피드백 루프를 형성하는 통합 시스템
    ![CPS](/assets/img/posts/Embedded_2/cps.png){: .s30 }
    * 설계 과정
        1. 모델링
        2. 디자인 - 실제 동작 가능한 구조물 창출
        3. 분석

#### 2) 실전 사례: Stanford STARMAC 드론 시스템 (MCU와 MPU의 분업)
실제 드론 시스템에서는 MPU와 MCU가 다음과 같이 분업합니다:

```
[ MPU: PC/104 (Pentium M / Linux) ]  ➔  경로 계획 & 상태 추정 (Soft Real-time)
              │ (UART 통신)
[ MCU: Robostix (ATmega128 / Bare-metal) ] ➔  100Hz 모터 추력 제어 (Hard Real-time)
```
=> 
  1. MCU와 MPU 분업(MCU가 저수준 정밀 판단&실시간 제어 <-> MPU가 고수준 판단)
  2. 실시간성(Dead-line)이 엄격한 모터 제어일수록 bare-metal MCU를 하드웨어 가까이에 둠. (++OS가 있으면 예측할 수 없는 시간 지연 발생할 수 있어서)
