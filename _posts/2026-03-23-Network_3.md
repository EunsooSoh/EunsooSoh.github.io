- **DNS 개요 및 서비스:** DNS는 사람이 읽기 쉬운 호스트 이름(예: cs.umass.edu)을 32비트 IP 주소로 변환하는 분산 데이터베이스이자 애플리케이션 계층 프로토콜. IP 주소 변환 외에도 호스트 및 메일 서버 별칭 제공, 트래픽 부하 분산(Load distribution) 등의 서비스를 제공
- **계층적 분산 구조:** 단일 장애점, 막대한 트래픽, 유지보수 한계 등 중앙 집중식 구조의 확장성 문제 때문에 DNS는 분산 계층 구조를 사용. 전체 시스템은 ICANN이 관리하는 전 세계 13개의 루트(Root) DNS 서버, .com이나 .edu 등을 담당하는 최상위 도메인(TLD) 서버, 그리고 각 기관이 직접 관리하는 책임(Authoritative) DNS 서버로 구성. 또한, 호스트의 쿼리를 대신 전달하고 캐싱하는 로컬 DNS 서버(계층 구조에 엄격히 속하지는 않음)가 존재
- **이름 확인(Resolution) 방식:**
    - 반복적(Iterated) 쿼리: 쿼리를 받은 서버가 다음으로 연락해야 할 서버의 이름을 알려주는 방식
    - 재귀적(Recursive) 쿼리: 연락받은 서버가 이름 변환에 대한 모든 책임(Burden)을 지고 직접 최종 응답을 반환하는 방식
        - 재귀적 쿼리 시나리오
            1. **요청 호스트** → **로컬 DNS 서버:** 호스트가 먼저 자신의 로컬 DNS 서버에 IP 주소를 질의
            2. **로컬 DNS 서버** → **루트(Root) DNS 서버:** 로컬 서버가 답을 모를 경우, 루트 DNS 서버에 직접 질문을 던짐 (바로 루트로!!)
            3. **루트 DNS 서버** → **TLD DNS 서버:** 루트 서버 역시 답을 모르면, 다시 하위 계층인 TLD 서버(.edu를 담당하는 서버)에 질문을 전달
            4. **TLD DNS 서버** → **책임(Authoritative) DNS 서버:** TLD 서버가 마지막으로 해당 도메인을 관리하는 책임 DNS 서버에 질문을 전달
            5. **응답의 역순 전달:** 책임 DNS 서버가 최종 IP 주소를 찾아 TLD DNS 서버로 응답을 보내면, 이 응답은 다시 'TLD → 루트 → 로컬 DNS → 요청 호스트'의 역순으로 거슬러 올라오며 전달
- **DNS 캐싱:** 응답 속도를 높이기 위해 DNS 서버는 학습한 매핑 정보를 일정 시간(TTL) 동안 캐시. 단, 정보가 즉시 업데이트되지 않아 일시적으로 Out-of-date 가능성이 있는 Best-effort 변환 방식
- **DNS 레코드(RR)와 메시지 포맷:** DNS 데이터베이스는 자원 레코드(RR)를 
`(name, value, type, ttl)` 형식으로 저장
    
    타입:
    
    - A(hostname - IP address)
    - NS(domain - 이 도메인이 가지고 있는 책임 서버의 hostname)
    - CNAME(별칭 - hostname)
    - MX(domain - 이 도메인 관련 SMTP mail server)
    
    DNS 쿼리와 응답 메시지는 동일한 포맷을 공유, 식별자, 플래그, 질문, 답변, 권한 정보, 추가 정보 영역으로 구성 (참고만)
    
- **도메인 등록:** 도메인을 등록하려면 DNS 등록 대행기관(Registrar)에 책임 이름 서버의 정보(type = NS, A)를 제공하여 TLD 서버에 삽입해야 함
    - TLD 서버에서 가지고 있어야 하는 것: NS, A 
    = 해당 도메인을 관리하는 책임 서버가 누구인지, 그리고 그 책임 서버의 IP주소가 뭔지
    - 책임 서버가 가지고 있어야 하는 것: A, MX
    = 도메인 내 서비스 호스트 이름에 대한 최종 IP 주소, 이 도메인 관련 메일 서버
