**1. 네트워크 계층의 2가지 핵심 기능**

네트워크 계층 프로토콜은 호스트와 라우터를 포함한 모든 인터넷 기기에 존재하며, 크게 **포워딩(Forwarding)**과 **라우팅(Routing)**이라는 두 가지 핵심 기능으로 구분

![라우터 아키텍처: 여러 입출력 포트와 Routing Algorithm(제어 평면), 각 포트의 local forwarding table(데이터 평면)의 관계를 보여주며, 헤더 값 0111이 입력되면 forwarding table을 조회해 출력 포트 2로 나가는 과정](/assets/img/posts/Network_10/image.png)

- **포워딩 (데이터 평면, Data Plane):**
    - **역할:** 라우터의 입력 링크로 들어온 패킷을 적절한 출력 링크로 이동
    - **특징:** 단일 라우터 내부에서 처리되는 **지역적(local) 기능**이며, 자동차 여행에 비유하면 '하나의 교차로(interchange)를 통과하는 과정'
    - **처리:** 하드웨어에 의해 나노초(nanosecond = 10^-9) 단위의 매우 빠른 속도로 동작
- **라우팅 (제어 평면, Control Plane):**
    - **역할:** 패킷이 출발지에서 목적지까지 이동하는 전체 경로를 결정
    - **특징:** 네트워크 전체(network-wide)를 아우르는 **전역적 논리**이며, 자동차 여행에서 '전체 여행 경로를 계획(planning)하는 과정'
    - **처리:** 소프트웨어 기반의 **라우팅 프로세서**에 의해 밀리초(millisecond = 10^-3) 단위로 동작

**2. 제어 평면(Control Plane)의 2가지 접근 방식**

라우팅을 통해 포워딩 테이블을 구성하는 방식

- **전통적인 라우팅 알고리즘 (Traditional):** 각 라우터 내부에 개별적인 라우팅 알고리즘 컴포넌트가 존재하여, 라우터들끼리 논리적 링크로 상호작용하며 제어 평면을 구성
- **소프트웨어 정의 네트워킹 (SDN):** 논리적으로 중앙 집중화된 원격 컨트롤러(Remote Controller)가 경로를 계산한 뒤, 각 라우터에 포워딩 테이블을 내려받아 설치(install)하는 방식

**3. 라우터 아키텍처의 핵심 구성 요소**

라우터는 크게 4가지 컴포넌트로 구성

1. **입력 포트 (Router Input Ports):** 데이터 평면 역할 수행 (하드웨어)
2. **스위칭 패브릭 (Switching Fabric):** 입력 포트와 출력 포트를 고속으로 연결하는 역할 수행 (하드웨어)
3. **출력 포트 (Router Output Ports):** 데이터 평면 역할 수행 (하드웨어)
4. **라우팅 프로세서 (Routing Processor):** 제어 평면 역할 수행 (소프트웨어)

**4. 입력 포트(Input Port)의 기능 및 처리 과정**

입력 포트로 데이터가 들어오면 다음과 같은 순서로 처리

- **L1: Physical layer (Line termination):** 비트(bit) 수준의 수신을 처리
- **L2: Link layer:** 이더넷과 같은 링크 계층의 수신을 처리
- **L3: 조회, 포워딩, 큐잉 (Lookup, Forwarding, Queueing):** 분산 스위칭(Decentralized switching) 기술을 활용하여 처리
    - **분산 스위칭:** 중앙 프로세서를 거치지 않고 입력 포트 메모리에 있는 포워딩 테이블을 사용하여 직접 출력 포트를 찾음 ("Match plus action"). 패킷이 들어오는 '회선 속도(Line speed)'에 맞춰 입력 포트 처리를 완료하는 것이 목표 (그래야 큐잉 지연이 안 생기니까)
- **포워딩의 2가지 종류:**
    - **목적지 기반 포워딩 (Destination-based forwarding):** **목적지 IP 주소만**을 기반으로 전달하는 전통적 방식
    - **일반화된 포워딩 (Generalized forwarding):** 헤더 필드 값의 다양한 조합을 기반으로 전달하는 방식

**5. 가장 긴 프리픽스 매칭 (Longest Prefix Matching, LPM)과 TCAM**

- **LPM:** 목적지 IP 주소를 기반으로 포워딩할 때, 앞에서부터 **가장 길게 일치하는**(가장 구체적인) 주소 프리픽스(Prefix)를 가진 링크 인터페이스를 선택하여 패킷을 전송
- **TCAM (Ternary Content Addressable Memory) 활용:** 이 방식은 TCAM이라는 특수 메모리를 통해 수행. TCAM은 테이블의 크기와 관계없이 주소를 제시하면 **단 한 번의 클럭 사이클(1 clock cycle)** 만에 목적지 주소를 검색해 낼 수 있음 (예: Cisco Catalyst 라우터는 TCAM에 약 100만 개의 라우팅 테이블 항목 저장 가능)

**6. 스위칭 패브릭 (Switching Fabric)의 3가지 구조**

패킷을 입력 포트에서 출력 포트로 전달하는 스위칭 패브릭의 이상적인 스위칭 속도

=$N(입력 포트 수) \times R(회선 속도)$
(최대로 들어오는 속도)

하드웨어 구현 방식에 따라 3가지로 분류. 아래로 갈수록 더 빨라진다고 보면 됨

1. **메모리를 통한 스위칭 (Memory):**
    - 1세대 라우터 방식 (전통적 컴퓨터 구조)
    - 패킷이 시스템 메모리로 복사된 후 출력 포트로 이동하므로, 데이터그램당 공유 버스를 2번 통과해야 함. 따라서 속도가 **메모리 대역폭에 의해 제한**
2. **버스를 통한 스위칭 (Bus):**
    - 입력 포트 메모리에서 출력 포트 메모리로 공유 버스를 통해 직접 전달
    - **버스 경합(Bus contention):** **한 번에 하나**의 패킷만 버스를 통과할 수 있어, 전체 스위칭 속도가 **버스 대역폭**으로 제한 (예: Cisco 5600 라우터의 32 Gbps 버스는 액세스 라우터용으로 충분함)
3. **상호연결 네트워크를 통한 스위칭 (Interconnection Network / Crossbar):**
    - 버스 대역폭의 한계를 극복하기 위해 다수의 경로를 격자 형태로 구성
    - **Cisco CRS 라우터 예시:** 8개의 스위칭 평면과 3단계(3-stage) 상호연결 네트워크로 구성되어 있으며, 수백 Tbps 급의 막대한 스위칭 용량을 제공

**7. 큐잉 (Queueing) 발생 원인**

만약 스위칭 패브릭의 처리 속도가 결합된 입력 포트들의 수신 속도보다 느리다면, 스위칭 패브릭으로 들어가지 못한 패킷들이 **입력 큐(Input queues)에 쌓이게 됨**. 이로 인해 입력 버퍼 오버플로우가 발생하면 큐잉 지연(Queueing delay)과 패킷 손실(Packet loss)이 발생

- 입력포트 큐잉
    
    **HOL 블로킹 (Head-of-the-Line blocking):** 큐의 맨 앞에 있는 패킷이 출력 포트 경합 등으로 인해 스위치 패브릭을 통과하지 못하고 막혀버리면, 그 뒤에 줄 서 있는 패킷들은 목적지 출력 포트가 비어 있더라도 나아가지 못하고 갇히게 되는 현상
    
- **출력포트 큐잉**
    - 스위치 패브릭(Switch Fabric)을 통해 **패킷이 도착하는 속도**가 출력 링크(Output Link의 'R')로 빠져나가는 전송 속도보다 **빠를 때** 발생
    - **Drop Policy (폐기 정책): 여유 버퍼가 없을 때 "어떤 원칙으로 어떤 데이터그램을 버릴 것인가?"를 결정**
        - **Tail drop**: 가장 일반적인 방식으로, "**제일 늦게** 큐에 들어온 애"를 폐기
        - **Priority drop**: 패킷의 우선순위에 따라 덜 중요한 패킷을 먼저 폐기
    - **Scheduling Discipline (스케줄링 정책): 큐에 대기 중인 데이터그램 중 "어떤 것을 먼저 전송할 것인가?"를 결정**
- **버퍼 크기**
    - **적정 버퍼 크기 공식:**
        - 과거 경험 법칙 (RFC 3439): $RTT \times 링크 용량(C)$
        - 최근 권장 방식: 흐름(Flow)이 N개일 때, $\frac{RTT \times C}{\sqrt{N}}$
    - **버퍼 크기에 따른 트레이드오프:**
        - **버퍼가 너무 작을 때:** 스위칭 패브릭이 빠르면 **패킷 손실(Loss)이 증가 → 재전송**이 빈번해져 네트워크 도로(대역폭)를 낭비 **→ 링크 활용도가 감소**
        - **버퍼가 너무 클 때:** 큐에서 대기하는 시간이 늘어나 **지연(Delay)이 증가** → 실시간 애플리케이션의 성능 저하와 느린 TCP 응답을 유발
- 버퍼 관리 기법 (Buffer Management)
    - **Marking** (출력 포트에서 수행): 패킷을 폐기하기 전, 라우터(네트워크)가 패킷(IP datagram)에 marking해서 송신자에게 "현재 혼잡하다"는 혼잡 신호를 줌 (예: ECN, RED 기법)
- 패킷 스케줄링 정책 (Packet Scheduling Policies)
    
    큐에 쌓인 패킷을 내보내는(링크에 싣는) 순서를 결정하는 방법
    
    1. **FCFS (First-Come, First-Served / FIFO)**
        - 그냥 큐에 들어온 순서대로 전송
    2. **Priority Scheduling (우선순위 스케줄링)**
        - 높은 우선순위 큐에 있는 것 먼저 처리
        - 낮은 순위 패킷이 전송 대기 중이어도 높은 순위 패킷이 오면 중간에 껴서 먼저 전송. 단, 동일한 우선순위 내에서는 FCFS
    3. **Round Robin (RR, 라운드 로빈)**
        - 여러 클래스 큐를 순회하며 각 큐에서 패킷을 하나씩 전송
    4. **Weighted Fair Queuing (WFQ, 가중 공평 큐잉)**
        - Round Robin을 일반화한 것, "최대한 공평하게 하되 각 클래스마다 가중치(비율)를 두고 뺑뺑이"
        - 트래픽 클래스별로 최소 대역폭(1초에 최소 이만큼의 데이터 전송 = 즉, 전송률 보장)을 보장
