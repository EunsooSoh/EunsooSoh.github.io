**1. 트랜스포트 계층 서비스와 프로토콜**

- **역할:** 서로 다른 호스트에서 실행되는 애플리케이션 '프로세스 간'의 Logical communication을 제공. 트랜스포트 계층은 엔드 시스템에서 동작
- **송수신 동작:** 송신 측은 애플리케이션 메시지를 세그먼트(Segment)로 분할하여 네트워크 계층으로 전달, 수신 측은 세그먼트를 메시지로 재조립하여 애플리케이션 계층에 전달
- **계층 간 비교:**
    - 네트워크 계층(IP)은 '**호스트**(집) 간'의 통신(우편 배달부의 역할)
    - 트랜스포트 계층은 '**프로세스**(집 안의 아이들) 간'의 통신(집 안에서 편지를 나눠주는 역할)

**2. 주요 인터넷 트랜스포트 프로토콜 & 소켓 프로그래밍**

- **TCP (Transmission Control Protocol):** 신뢰성 있고 순서가 보장되는 전송, 혼잡 제어(Congestion control), 흐름 제어, 그리고 연결 설정(Connection setup) 서비스를 제공
    - 연결O
        
        ⇒ 클라이언트가 서버에 접속해서 TCP 연결을 먼저 하고, 서버에서 열리는 소켓 2개 존재
        
        (1) welcoming socket: 항상 열려 있고, 최초 접속 요청을 맞이
        
        (2) connection socket: 특정 클라이언트랑만 통신
        
    - 흐름
        1. socket(AF_INET, SOCK_STREAM)으로 소켓 생성
        2. bind(IP 주소, port#) → listen()으로 TCP 요청 듣기 시작
        3. 요청 오면 accept() 호출
        4. 해당 요청 수락하고 새로운 소켓 반환
            
            이 소켓으로
            
            1. recv() 읽음
            2. send() 씀
        5. 통신이 끝나면 이 개별 소켓을 닫음
- **UDP (User Datagram Protocol):** 신뢰성이 없고 순서가 보장되지 않는 전송, IP에 최소한의 기능(no-frills)만 추가한 프로토콜
    - 연결X 전송
        
        ⇒ 매 패킷을 보낼 때마다 목적지의 IP 주소, port # 명시 필요(받은 애도 받은 패킷에서 보낸 애의 IP 주소, port # 추출)
        
    - datagram이라는 덩어리로 주고받음
    - Congestion control X → sender가 원하는 만큼 보냄
    - 흐름
        1. socket(AF_INET, SOCK_DGRAM)으로 소켓 생성
        2. bind(도착지의 IP 주소, port#)로 소켓이랑 포트 번호 바인딩, 무한 루프 돌리면서 대기
        3. 데이터 오면 revfrom()으로 메시지, 클라이언트 주소 한 번에 읽어서 처리 결과를 주소랑 같이 sendto()로 전송
        4. 소켓 닫음
    - ex: DNS, SNMP, HTTP/3 → application layer에 reliable, congestion control 추가
- **제공하지 않는 서비스:** TCP와 UDP 모두 지연 시간 보장같은 timing이나 minimum throughput 보장 서비스는 제공하지 않음

**3. 다중화(Multiplexing)와 역다중화(Demultiplexing)**
이 과정은 모든 계층에서 공통적으로 발생, 세그먼트의 헤더 정보를 이용해 통신을 분류

- **Multiplexing(sender):** 여러 소켓에서 생성된 데이터를 모아서 트랜스포트 헤더를 추가하여(=segment) 네트워크 계층으로 전달하는 과정
- **Demultiplexing(receiver):** 네트워크 계층에서 올라온 세그먼트의 헤더 정보(IP 주소와 포트 번호 등)를 확인하여, 이를 올바른 애플리케이션 소켓으로 분배하는 과정

**4. 역다중화의 동작 방식 (UDP vs TCP)**

- **비연결형 역다중화 (UDP):** UDP 소켓은 오직 목적지의 포트 번호(Destination port number)만을 확인하여 역다중화를 수행 (cf. 받는 건 IP 주고, Port #)
- **연결 지향형 역다중화 (TCP):** TCP 소켓은 출발지 IP, 출발지 포트 번호, 목적지 IP, 목적지 포트 번호라는 **4-tuple(4가지 값 모두)**을 사용하여 세그먼트를 올바른 소켓으로 연결. 따라서 수신 측의 목적지 IP와 포트 번호가 완전히 동일하더라도, 클라이언트의 출발지 IP나 포트 번호가 다르다면 서버는 이를 구별하여 각각 다른 소켓으로 역다중화
