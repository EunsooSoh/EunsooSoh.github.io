### 1. 객체지향 데이터베이스 핵심 용어 매칭

- **객체 (Object):** 현실 세계의 개체를 추상적으로 표현한 것
- **객체 식별자 (OID):** 각 객체를 시스템 내에서 유일하게 구별해 주는 식별자
- **메서드 (Method):** 객체에 수행할 수 있는 연산으로, **객체의 속성 값을 조작**하는 역할
- **클래스 (Class):** 속성과 메서드를 공유하는 유사한 성질의 객체들을 그룹화한 틀
- **복합 객체:** '사용자 정의 클래스'를 도메인으로 하는 속성을 가진 객체
- **질의 특징:**
    - 질의 대상은 '클래스'
    - 질의의 결과는 해당 클래스에 속하는 '**객체 집합**'

### 2. 객체관계 데이터베이스

- **핵심 특징:** 관계 데이터 모델 + 객체지향 개념. 객체지향 개념을 지원하는 **표준 SQL을 그대로 사용 가능**

### 3. 분산 데이터베이스 시스템

물리적으로 분산되어 있지만 논리적으로는 하나의 중앙 집중식 시스템처럼 사용하는 시스템

**① 5가지 분산 투명성 (이름과 의미 연결 필수)**
사용자가 데이터베이스가 분산되어 있다는 사실을 눈치채지 못하게 하는 5가지 규칙

- **병행 투명성:** 여러 트랜잭션이 동시 수행되어도 항상 일관된 결과 유지
- **장애 투명성:** 특정 지역 시스템에 문제가 생겨도 전체 시스템은 계속 작동
- **위치 투명성:** 데이터의 실제 저장 위치를 몰라도 논리적 이름만으로 접근 가능
- **중복 투명성:** 데이터가 여러 곳에 중복 저장되어 있어도 사용자는 하나만 있는 것처럼 사용
- **단편화 투명성:** 릴레이션이 여러 조각으로 나뉘어 저장되어 있어도 사용자는 분할된 사실을 모름

**② 4가지 스키마 구조**

- **전역 개념 스키마 → 단편화 스키마 → 할당 스키마 → 지역 스키마** 순서로 구성
- **장점:** 신뢰성과 가용성 증가, 지역 자치성 및 효율성, 확장성 지원
- **단점:** 개발 및 관리 비용이 크게 증가

### 4. 데이터 웨어하우스의 4대 특징

데이터베이스에서 의사 결정에 필요한 데이터만 미리 추출·변환하여 통합한 **'읽기 전용'** 저장소. 4가지 키워드

1. **주제 지향적:** 업무 처리 중심이 아닌, '의사 결정 주제' 중심으로 데이터 구성
2. **통합적:** 여러 데이터베이스에서 추출한 데이터를 일관된 형태로 통합 저장
3. **비소멸성:** 삽입/수정/삭제 없이 한 번 저장되면 검색(읽기) 작업만 수행됨
4. **시간에 따라 변화 (Time-variant):** 동향 분석을 위해 현재 데이터뿐만 아니라 과거의 스냅샷 데이터도 함께 유지
