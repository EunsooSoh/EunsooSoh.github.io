1. 동기화
    - 필요성: 멀티스레트 환경에서는 여러 실행 흐름이 메모리를 공유 → 실행 순서에 따라 결과가 달라지거나 상태가 붕괴되는 문제 발생
    - 문제 상황
        
        (1) 비원자성
        
        ++, — 같은 게 기계어 수준에서 load → add/sub → store 3단계이기 때문에 critical section을 실행할 때, load, store 사이에 끼어들면 나중에 계산된 값으로 덮어씌우는 Lost Update 발생 → overflow, underflow
        
        ```c
        // Producer
        while (1) {
            item = produce();
            while (count == N) ; // 버퍼가 가득 참 : 대기
            buffer[in] = item;
            in = (in + 1) % N;
            count++; // 위험!
        }
        
        // Consumer
        while (1) {
            while (count == 0) ; // 버퍼가 비어 있음 : 대기
            item = buffer[out];
            out = (out + 1) % N;
            count--; // 위험!
            consume(item);
        }
        ```
        
        - 만약에 producer 여러 개, consumer 여러 개이면 in, out, buffer 같은 변수도 공유하는 것이기 때문에 덩어리로 보호해야
        
        (2) Race condition
        
        여러 실행 흐름이 같은 공유 상태를 동시에 조작할 때, 타이머 인터럽트나 시스템 콜 등으로 인한 인터리빙(실행 순서 섞임)에 의해 결과가 달라지는 현상
        
        ⇒ 동기화 = 프로그램이 유지해야 할 상태 관계의 보호
        
        ```c
        // [동기화가 필요한 코드] - 공유 변수 수정
        int balance = 1000; // shared
        void deposit(void) {
            balance += 100; // load-add-store 비원자적 접근
        }
        void withdraw(void) {
            balance -= 100; // load-sub-store 비원자적 접근
        }
        
        // [동기화가 불필요한 코드] - 읽기 전용 및 지역 변수
        const int N = 1024; // read-only (공유하는 건 읽기만 수행)
        void worker(void) {
            int local_sum = 0; // thread-local (각 스레드 전용)
            local_sum += N;
        }
        ```
        
2. 임계 구역
    
    **entry section**(들어가도 되는지 결정) → **critical section**(공유 상태 갱신) → **exit section**(다음 대기자에게 기회) → remainder section(공유 상태와 무관한 코드)
    
    - 필수 조건3
        
        (1) 상호 배제(Mutual exclusion): 한 순간에 오직 하나의 실행 흐름만 임계 구역에 진입할 수 있어야 함
        
        ```c
        if (!busy) { // 양쪽이 busy == false 동시에 읽으면 동시 진입 가능
        	busy true;
        	// 임계구역
        	busy = false;
        }
        ```
        
        (2) progress: 임계 구역이 비어 있고, 진입을 원하는 스레드가 있으면 무한정 지연X = 임계 구역 비어 있고 진입 원하는 스레드 있으면 넘겨줌
        
        ```c
        while(turn != i); // turn이 j인 상태에서 진입 안 하면 i 영구 차단
        // 임계 구역
        turn j;
        ```
        
        (3) Bounded Waiting(유한 대기): 특정 스레드가 진입을 요청한 후 허락될 때까지 다른 스레드들이 임계 구역에 진입할 수 있는 횟수에는 상한선이 존재 ⇒ 기아 방지(내 앞에 끼어드는 상한선이 존재)
        
        ```c
        while(test_and_set(&lock)); // 빠른 스레드가 lock 계속 선점 => 느린 애 기아
        // 임계구역
        lock = false;
        ```
        
3. 고전 해법: Peterson
    
    공유 변수
    
    bool flag[2] = {false, false}; // flag[i] = 프로세스 i가 들어가고 싶어요
    
    int turn=0; // turn: 누구 차례인지(둘 다 원할 때 누구에게 양보할지)
    
    - 0번 프로세스 기준
    
    ```c
    // entry
    flag[0] = true;
    turn = 1;
    while(flag[1] && turn == 1); // 다른 프로세스가 들어가고 싶어하고, 걔의 차례인 동안 기다림
    // 기다림이 끝남
    // 임계구역
    // exit 나가
    flag[0] = false; // 이제 안 들어가고 싶어요
    ```
    
    ⇒ **나중에 turn을 쓴 쪽이 양보**
    
    (1) 상호 배제: turn이 한 순간에 하나의 값만 가지니까 ok(둘 다 동시에 while을 빠져 나올 수 없음)
    
    (2) 진행: 
    
    - 한 쪽만 원하면 while문 false돼서 바로 들어감
    - 양 쪽 다 원하면 turn이 결정해줘서 또 들어가야 할 애는 바로 들어감
    
    (3) 한정 대기: 최대 한 번 선행
    
    - 진입하기 전에 늘 상대에게 turn을 넘기기 때문에 내 앞에 끼어드는 건 한 번뿐
    - 가정 및 파괴
        - 가정: 내가 쓴 순서대로 상대도 변수를 관찰한다
        - 현실: store를 store buffer에 잠시 보류 → 내가 쓴 flag 값이 상대에게 바로 안 보일 수 있음 → 두 코어가 서로 flag를 false로 읽어 동시에 임계구역 진입
4. 하드웨어 지원
    
    (1) atomic instruction: Read-Modify-Write 동작을 중간 개입 없이 한 번에 수행
    
    - **TAS**(점유): 지금 gate를 내가 바로 1로 바꿔 점유
    - CAS(조건부 교체): 0이면 1로 교체, 아니면 즉시 실패
    - FAA(번호표/카운팅): next 증가시키며 내 번호 확보
    
    (2) memory fence: 다른 코어도 같은 순서로 관찰 강제
    
    (3) cache coherence: 한 코어의 최신 쓰기 값을 다른 코어의 캐시에 전파
    
5. lock 방식2
    
    (1) Spinlock
    
    : busy waiting
    
    = 계속 확인
    
    → 컨텍스트 스위치 오버헤드 X but CPU 사이클 낭비
    
    ⇒ **임계 구역이 짧거나 멀티코어**
    
    (2) Mutex/sleep lock
    
    : 락을 획득하지 못하면 스레드 잠들고 락이 풀리면 깸
    
    - 락 획득 실패 → Waiting Queue에 들어가 Block 상태
        
        ! 락을 가지고 있던 게 unlock → Ready Queue에 들어감(스케줄링 기다림)
