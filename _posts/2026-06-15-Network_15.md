**1. Routing의 확장성 (Making routing scalable)**

이상적인 라우팅 환경과 달리, 실제 인터넷 환경에서는 라우팅 테이블 크기와 관리적 자율성 문제로 인해 계층적 접근이 필수적

- **Scale (규모):** 수십억 개의 목적지가 존재 → 모든 목적지를 라우팅 테이블에 저장할 수 없음
- **Administrative autonomy (관리적 자율성):** 각 네트워크 관리자는 자신의 네트워크 내에서 라우팅을 스스로 제어하기를 원함
    
    ⇒ **해결책 (AS):** 라우터들을 **AS(Autonomous Systems = domains)** 라는 영역으로 그룹화
    

**2. Intra-AS vs Inter-AS Routing**

AS 개념의 도입으로 라우팅은 내부 라우팅과 외부 라우팅으로 명확히 구분

| 구분 | 설명 |
| --- | --- |
| Intra-AS (Intra-domain) | 동일한 AS("network") 내에 있는 라우터들 간의 라우팅. 동일한 AS 내의 모든 라우터는 같은 intra-domain protocol을 실행 |
| Inter-AS (Inter-domain) | 서로 다른 AS들 간의 라우팅 |
| Gateway router | 자신의 AS 가장자리(edge)에 위치하며, 다른 AS의 라우터와 연결을 가짐. intra-domain과 inter-domain 라우팅을 모두 수행 |

**3. Intra-AS Routing Protocols (내부에 있는 라우터들끼리 길을 찾을 때)**

- 주요 프로토콜
    - **RIP (Routing Information Protocol):** 고전적인 distance-vector(DV) 기반 프로토콜 (거쳐가는 라우터의 개수만을 비용으로 계산)
    - **EIGRP (Enhanced Interior Gateway Routing Protocol):** DV 기반이며, 과거 Cisco 전용이었으나 2013년에 개방형 표준이 됨
    - **OSPF (Open Shortest Path First):** 공개적으로 사용 가능한 프로토콜. LS 기반
- OSPF 세부 특징
    - **Link-state (LS) 방식:** 모든 라우터가 전체 AS에 OSPF link-state advertisement를 플러딩(flooding: 내가 받은 것을 그대로 다른 라우터에 전달)
    - **직접 전송:** TCP/UDP를 사용하지 않고 IP 위에서 직접 전송
    - **Dijkstra algorithm 사용:** 각 라우터가 전체 토폴로지 정보를 가지고 다익스트라 알고리즘을 사용해 포워딩 테이블을 계산
    - 대역폭(bandwidth), 지연(delay) 등 다양한 link cost metric을 사용 가능
    - **보안:** 악의적인 침입을 막기 위해 모든 OSPF 메시지는 인증(authenticated)을 거침
- Hierarchical OSPF (계층적 OSPF)
    
    OSPF는 local area와 backbone의 2계층 구조(two-level hierarchy)로 구성
    
    - **Local routers:** 자신의 area 내부의 세부 토폴로지만 알며, area 내에만 LS를 플러딩(구역 내 모두 동일 정보 공유)
    - **Area border routers:** 자신이 속한 area의 목적지까지의 거리를 요약 → backbone에 advertise
    - **Backbone router:** backbone 영역으로 제한된 OSPF를 실행
    - **Boundary router:** 다른 AS들과 연결

**4. Inter-AS Routing Protocol: BGP (다른 AS에 있는 라우터들끼리 길을 찾을 때)**

BGP (Border Gateway Protocol)는 인터넷을 하나로 묶어주는 사실상의(de facto) 표준 inter-domain 라우팅 프로토콜. subnet이 자신의 존재와 도달 가능한 목적지 정보를 인터넷의 나머지 부분에 알릴 수 있게 함

- BGP Routes(reachability info): BGP가 알리는 경로 구성 (AS 리스트, 목적지 X의 주소)
    - **prefix(목적지)**
    - attributes(그곳으로 가는 경로)
        - **AS-PATH:** 경로 알림이 통과해 온 AS들의 목록. = 어떤 AS들을 거쳐가야 그 prefix로 갈 수 있을지에 대한 정보
        - **NEXT-HOP:** 다음 AS로 가기 위한 특정 내부 라우터(internal-AS router)
- BGP의 핵심 기능 4가지
    
    **(1) eBGP(external BGP):** 
    
    - gateway router들끼리 정보를 주고받을 때 사용
    - 이웃한 AS들로부터 reachability info를 얻음
    
    (2) reachability info를 policy 기반으로 어떻게 활용할지 결정
    
    **(3) iBGP(internal BGP):** 
    
    - eBGP로부터 알아온 도달 가능성 정보와 어떻게 활용할 건지에 대한 것을 모든 AS 내부 라우터에게 전파
    - **iBGP(내부)로 배운 소문은 다른 iBGP(내부) 이웃에게 다시 전달하지 않음**
    
    (4) neighbor에게 destination reachability info 전달(advertise)
    

- 문풀
    - gateway router가 eBGP로 현재 자신이 속한 AS 외부에 있는 목적지 X로 가는 path를 받음
        - 그 라우터가 돌리는 라우팅 프로토콜이 뭐든 외부에 대한 정보를 받아오고 알게 되는 건 iBGP나 eBGP
        
        → 내부 router들에게 X로 가고 싶으면 자기(X로 가는 path를 받아온 gateway router)한테 보내라고 함
        
        → 그래서 그 AS 내부 모든 라우터들은 dest가 X면 그 라우터(X로 가는 path를 받아온 gateway router)로 가게 forwarding table 구성
        
    
    추가
    
    - **BGP session:** 두 대의 BGP 라우터가 반영구적인(semi-permanent) TCP 연결을 통해 통신
    - **Path vector protocol:** 다양한 목적지 네트워크 prefix로 가는 경로(paths)를 알림 (비용은 모름)
- BGP Messages
    
    BGP 피어 간에 교환되는 메시지 유형은 4가지
    
    - **OPEN:** 원격 BGP 피어와 TCP 연결을 열고 발신자를 인증
    - **UPDATE:** 새로운 경로를 알리거나 기존 경로를 철회(withdraw)
    - **KEEPALIVE:** UPDATE 메시지가 없을 때 연결을 유지, OPEN 요청에 대한 ACK 역할도 수행
    - **NOTIFICATION:** 이전 메시지의 오류를 보고하거나 연결을 종료할 때 사용
- Policy-based Routing
    - **Import policy:** 경로 알림을 받은 게이트웨이는 수용할지 거부할지(예: 특정 AS를 거치는 경로는 거부)를 정책에 따라 결정
    - **Real world policy:** ISP는 자신의 customer network 간의 트래픽만 라우팅하기를 원하며, 다른 ISP들 사이의 transit traffic을 나르는 것을 원하지 않음
- **BGP Route Selection 우선순위**
    
    내부 라우터들이 경로를 선택하는 우선순위
    
    1. **Local preference value attribute:** 관리자의 정책적 결정 (Policy decision)
    2. **Shortest AS-PATH:** 가장 짧은 AS-PATH
    3. **Closest NEXT-HOP router:** 가장 가까운 넥스트 홉 (Hot potato routing)
        - **Hot potato routing:** inter-domain cost는 무시하고, intra-domain cost가 가장 적은(가장 가까운) 로컬 게이트웨이를 선택하여 패킷을 내보내는 방식
            
            ![Hot potato routing 예시: AS1의 게이트웨이 1c가 AS2를 거쳐 AS3의 목적지 X로 가는 경로를 받았을 때, AS2 내부에서 intra-domain cost가 더 낮은 게이트웨이(2a)를 선택해 패킷을 넘기는 다이어그램](/assets/img/posts/Network_15/image-1.png)
            
    4. **Additional criteria:** 기타 추가 기준
    
    ++ 경로가 하나밖에 없는데 인터페이스 결정해야 하면 그냥 최단거리 선택
    

**5. Intra-AS와 Inter-AS 라우팅 설계가 다른 이유**

- **Policy (정책):** Inter-AS에서는 관리자가 트래픽이 어떻게 라우팅되는지 엄격히 제어해야 하지만, Intra-AS는 단일 관리자 영역이므로 정책 이슈가 상대적으로 적음
- **Scale (확장성):** 계층적 라우팅을 통해 라우팅 테이블 크기와 업데이트 트래픽을 줄여야 함
- **Performance (성능):** Intra-AS는 성능 최적화에 집중할 수 있는 반면, Inter-AS는 성능보다 정책(policy)이 훨씬 더 중요하게 작용
