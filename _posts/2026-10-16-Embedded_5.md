### Part 1. GPIO (General-Purpose Input/Output)

#### 1. 개념 및 MMIO 제어

* **GPIO 개념:** 소프트웨어 설정 → 핀의 역할을 입력 또는 출력으로 변경 → 외부 장치와 디지털 신호를 주고받는 범용 인터페이스
* GPIO를 **MMIO**로 제어함
* **Port:** 여러 GPIO 핀 단위를 묶어서 관리하는 단위
    * 그래서 핀 읽을 때 port문자+핀번호로 읽음

#### 2. 출력 회로 (Push-Pull vs Open-Drain)

* **MOSFET 스위치:** GPIO 핀 내부에 스위치인 **P-FET, N-FET** 내장
    * P-FET:

        ![P-FET](/assets/img/posts/Embedded_5/p-fet.png){: .s70 }

    * N-FET:

        ![N-FET](/assets/img/posts/Embedded_5/n-fet.png){: .s70 }

* **Push-Pull (기본 출력):** P-FET과 N-FET이 번갈아 ON되어 **HIGH(3.3V)와 LOW(0V)를 모두 트랜지스터가 직접 만듦**
* **Open-Drain:**
    * N-FET만 동작
        * 켜짐 → LOW
        * 꺼짐 (LOW로 끌어내리기 그만둠) → 풀업 저항(Pull-Up R) 때문에 HIGH
    * 여러 장치가 라인을 공유하는 **I2C 버스, 레벨 변환, 와이어드 AND** 회로에 사용

#### 3. 입력 회로 (Pull-Up/Pull-Down & 슈미트 트리거)

* **부동(Floating) 방지:** 아무것도 연결되지 않은 입력 핀은 노이즈로 인해 전압이 불확정

    → 내부/외부 **풀업(Pull-Up, 기본 HIGH)** / **풀다운(Pull-Down, 기본 LOW)** 저항을 설정 → 기본값을 확정함

* **슈미트 트리거 (Schmitt Trigger):** 상승/하강 임계값($V_{TH}, V_{TL}$)을 다르게 두고 그 구간을 히스테리시스 구간이라고 함
    * 이걸 이용해 입력 신호 경계에서의 출렁임(채터링/노이즈)을 방지

        ![슈미트 트리거](/assets/img/posts/Embedded_5/schmitt-trigger.png){: .s70 }

#### 4. 전류 한계 및 안전 설계

* **전류 예산:** 칩 전체 최대 전류 고려해서 해야 함

#### 5. 주요 레지스터 & BSRR / AF 모드

* **주요 레지스터:**
    * `MODER` (입출력/AF/아날로그 모드)
    * `IDR` (입력 읽기)
    * `ODR` (출력 쓰기)
* **BSRR (Bit Set/Reset Register):** RMW로 인해 인터럽트 발생 시 값이 오염될 수 있는 ODR(출력 쓰기)과 달리, **원자적 SET/RESET**을 수행
* **Alternate Function (AF 모드,** `MODER=10`**):** 출력 드라이버의 input을 `ODR`에서 내부 주변장치(USART_TX, SPI_SCK, TIM_CH 등)로 전환
    * 모드 설정: `MODER=10`으로
    * 출력 방식: 여전히 `OTYPER`로 출력 드라이버의 출력 방식 push-pull/open-drain 결정

    ![GPIO 출력 드라이버](/assets/img/posts/Embedded_5/gpio_output_driver.png){: .s70 }

### Part 2. PWM

#### 1. 정의

* **Pulse Width Modulation:** 디지털 신호의 HIGH 시간 비율을 조정해서 평균 전압 제어
* **Duty Cycle:** HIGH인 시간

    → 이걸 조절해서 디지털 핀이 0V와 3.3V만 출력 가능한데 그 중간처럼 보이게 평균 전압을 제어

#### 2. 하드웨어 타이머 관련 레지스터

* **PRESCALER (PSC):** 타이머 입력 클록을 몇 번에 카운터를 한 번 올릴지 결정
* **PERIOD (ARR, Auto-Reload Register):** 카운터 최댓값(몇 번까지 세고 0으로 돌아갈 건지) 정함 → **PWM 주파수**(1/PWM 주기) 결정
* **COMPARE (CCR, Capture/Compare Register):** HIGH 유지 길이(Duty Cycle)

### Part 3. 통신

#### 1. 직렬(Serial) vs 병렬 통신

* **병렬:** 빠르지만 MCU의 핀 수 폭증
* **직렬:** 1~2개 핀으로 비트를 순차 전송

#### 2. UART (Universal Asynchronous Receiver/Transmitter)

* **비동기 통신:** 클록 선이 없으므로 송수신자가 동일한 **Baud Rate(초당 비트 수)** 를 사전에 약속해야 함
    * 안 맞추면 프레임 에러 or 데이터 손실
* cf. USART: 클락 있어서 클락 속도로 맞추면 됨 (근데 CLK 선 하나 추가됨)
* **Polling:** CPU가 직접 상태 플래그를 반복해서 확인하면서, 데이터가 준비되면 그때 처리하는 방식

    예시 코드

    ```c
    // 수신 (폴링)
    while (!(USART->SR & RXNE)) { }   // 데이터 올 때까지 계속 확인
    data = USART->DR;                  // 도착하면 읽음

    // 송신 (폴링)
    while (!(USART->SR & TXE)) { }    // 송신 준비될 때까지 계속 확인
    USART->DR = data;                  // 준비되면 씀
    ```

    * busy-wait라 CPU 낭비

        → **인터럽트(Interrupt)** 방식으로 해결

        * 등록해놓고 CPU는 다른 일 하다가 HW가 이벤트(수신 완료 등) → 인터럽트 발생 → CPU가 핸들러 실행 → 핸들러가 콜백 함수 호출
            * 콜백 함수는 해당 이벤트에 대해서 내 프로그램이 실행해야 할 코드

#### 3. 직렬 프로토콜 3종

* 속도 우선: **SPI** (일반적으로 UART < I2C << SPI)
    * SPI: Full Duplex (송수신을 동시에 하는 방식)
* 핀 절약 + 다수 장치: **I2C**
    * I2C: 2핀을 공유하고 각 센서에 7비트 주소(127개) 부여해서 여러 장치 하나의 버스에 연결 가능
* 간단한 1:1: **UART**

### Part 4. AMBA 버스 아키텍처 및 중재 (Bus & Arbitration)

#### 1. AHB vs APB 버스 분리

* **AMBA**
    * **A**dvanced **M**icrocontroller **B**us **A**rchitecture
    * ARM이 정의한 온칩 버스 표준
    * 고속 버스(AHB), 저속 버스(APB) 분리
        * **AHB**
            * 고속 버스
            * Advanced High-performance Bus
            * CPU, SRAM, DMA(고속 장치)와 연결
        * **APB**
            * 저속 버스
            * Advanced Peripheral Bus
            * UART, Timer, GPIO(저속 장치)와 연결

        ⇒ 고속 마스터 트래픽이 저속 주변장치에 의해 방해받는 현상 예방

#### 2. RCC (Reset and Clock Control)

* 주변장치는 전원이 들어와도 **RCC에서 해당 클록 게이트(Clock Gate)를 켜기 전까지 레지스터도 응답 X**

#### 3. Bus Matrix & 중재

* 마스터(CPU, DMA1, DMA2) X 슬레이브(Flash, SRAM1/2, AHB1/2) 교차 연결

    ![Bus Matrix](/assets/img/posts/Embedded_5/bus-matrix.png){: .s70 }

* 접근
    * 서로 다른 슬레이브에 접근 → 대기 없이 동시 처리 가능
    * 동일한 슬레이브에 동시 접근 → 중재기(Arbiter)가 우선순위에 따라 순서 결정
