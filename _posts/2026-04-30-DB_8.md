: ER 모델, 릴레이션 변환 규칙으로 데이터베이스 설계

단계

1. 요구사항 분석 ⇒ 요구사항 명세서
    
    : 필요한 데이터나 처리를 파악, DB 용도 파악
    
2. 개념적 설계 ⇒ 개념적 스키마 = **ER 다이어그램**
    
    요구사항 명세서로부터
    
    (1) 명사 → 개체와 속성 추출
    
    (2) 동사 → 관계 추출
    
    - 이 관계에 대한 매핑 카디널리티, 참여 특성도 결정
    
    (3) ER 다이어그램 작성
    
3. 논리적 설계 ⇒ 논리적 스키마 = 릴레이션 스키마
    
    ER다이어그램을 논리적 스키마로 변환하는 규칙 5가지
    
    (1) 모든 개체 → 릴레이션으로
    
    - 개체 이름 → 릴레이션 이름
    - 개체 속성 → 릴레이션 속성
        - 복합 속성은 그걸 구성하는 단순 속성만 릴레이션 속성으로 들어감
        - 개체 키 속성 → 릴레이션 기본키
    
    (2) 다대다 관계 → 릴레이션
    
    - 관계 이름 → 릴레이션 이름
    - 관계 속성 → 릴레이션 속성
    - 각 측의 기본키를 외래키로 하고, 그 외래키들을 조합해서 하나의 기본키로 하든지, 
    각각을 외래키로 하고 새로운 기본키를 만들든지
    
    (3) 일대다 관계 → 외래키
    
    - 기본) 1측의 기본키를 n측 외래키로
    - 특수: 약한 개체를 포함) 1측의 기본키를 n측의 외래키로 들여오고 그걸 포함해서 **원래 기본키랑 같이 하나의 기본키로**
    
    (4) 일대일 관계 → 외래키
    
    - 기본) 서로의 기본키를 외래키로 교환
    - 특수1: 하나만 필수) 필수적으로 참여하는 개체의 릴레이션만 상대로부터 외래키 받음
    - 특수2: 둘 다 필수) 각각의 기본키를 외래키로 하나의 기본키를 만들어서 새로운 릴레이션 하나로
    
    **(5) 다중값 속성 → 독립 릴레이션**
    
    다중값을 가지는 릴레이션의 기본키를 외래키로 갖는 릴레이션을 만들고(독립 릴레이션), 다중값 속성이랑 외래키 조합해서 기본키로
    
    ![다중값 속성의 독립 릴레이션 변환 예시: 사원 개체의 다중값 속성인 부하직원을, 사원번호(외래키)와 부하직원을 묶어 기본키로 하는 별도의 사원-부하직원 릴레이션으로 분리하는 다이어그램](/assets/img/posts/DB_8/image.png)
    
    추가)
    
    ![재귀적(자기 참조) 관계의 변환 예시: 사원-관리(1:n)-사원처럼 사원 개체가 자기 자신과 맺는 관계를, 사원 릴레이션에 상사번호라는 외래키 속성을 추가해 표현하는 다이어그램](/assets/img/posts/DB_8/image-1.png)
    
    ⇒ 이렇게 **릴레이션 스키마로 변환한 후, 테이블 명세서** 작성
    
    - 관계의 속성
        - 1:n 무조건 n에
        - 1:1 필수인 쪽에. 둘 다 선택이면 그냥 아무데나
    
    테이블 명세서: 
    
    - 릴레이션 스키마에 대한 설계 정보를 기술한 문서
    - 데이터 타입, null 허용 여부, 제약조건 등 기술
    
4. 물리적 설계 ⇒ 물리적 스키마
    
    하드웨어, OS를 고려해서 처리 효율을 높이기 위한 설계를 함
