## 1. 연산 구조

* Single Compute Engine
    - 하나의 강력한 연산 장치(엔진)가 모든 종류의 연산을 순차적으로 처리.
    - 구조가 단순하고 제어하기 쉽지만, 하나의 연산 장치가 모든 종류의 연산을 다 해야 하므로 대규모 데이터를 처리할 때는 속도가 느림.


* Layer-pipelined Dataflow
    - AI 모델의 여러 Layer를 각각 담당하는 연산기들을 컨베이어 벨트처럼 일렬로 배치하는 구조.
    - 1번 층이 연산을 끝내고 결과를 2번 층으로 넘기면, 1번 층은 쉬지 않고 바로 다음 데이터를 받아 처리. => 데이터가 끊임없이 흘러가기 때문에 효율이 매우 높음.


* Systolic Array
    - 구글의 TPU 등에서 핵심적으로 사용하는 행렬 연산기 구조.
    - 작은 연산기(MAC)들을 바둑판 모양(2D 배열)으로 촘촘하게 배열. 
    - 데이터가 파도 타듯 한쪽에서 들어와서 연산기를 거치며 옆으로, 아래로 규칙적으로 전달됨.
    - 메모리에서 데이터를 한 번만 가져와도 여러 연산기가 돌려가며 쓸 수 있음 -> 메모리 접근은 최소화, 연산량은 극대화하는 구조.

## 2. 메모리 최적화

* Double Buffering (Ping-Pong Buffer)
    - 데이터를 저장하는 버퍼(메모리 공간)를 두 개(Ping과 Pong) 만들어 두는 기법.
    - 가속기가 'Ping' 버퍼에 있는 데이터를 가져와 열심히 계산하는 동안, 메모리는 다음 처리할 데이터를 미리 'Pong' 버퍼에 채워 넣음.
    - 계산이 끝나면 역할을 바꿔서 가속기는 'Pong'을 읽고 메모리는 'Ping'을 채움. => 계산 장치가 데이터를 기다리며 노는 시간을 완전히 없앰.

## 3. 루프 최적화 (반복문을 하드웨어에 맞게 쪼개기)

* Loop Unrolling
    - ex. for (i=0; i<4; i++) 처럼 4번 반복해야 하는 코드를 하드웨어 연산기 4개를 복사해서 한 번에 병렬로 끝내버리는 기법. 
    - 공간(실제 연산기 회로들이 차지하는 물리적인 면적)을 많이 쓰는 대신 속도를 크게 높임.


* Loop Tiling (Blocking)
    - 처리해야 할 데이터가 너무 커서 빠른 내부 메모리(BRAM 등)에 한 번에 안 들어갈 때 사용.
    - 큰 데이터를 하드웨어 버퍼 크기에 딱 맞게 작은 Tile로 쪼갠 뒤, 한 조각씩 가져와서 연산하는 기법. 
    - 느린 외부 메모리(DDR)에 접근하는 횟수를 확 줄여줌.


* Loop Interchange
    - 다중 반복문(중첩된 for문)에서 바깥쪽 루프와 안쪽 루프의 순서를 뒤바꾸는 기법.
    - 메모리에 저장된 데이터의 물리적 순서(행렬의 가로/세로 방향)에 맞게 읽어오도록 순서를 바꿈 -> 캐시 효율이 좋아짐 -> 데이터를 훨씬 빠르게 가져올 수 있음.
