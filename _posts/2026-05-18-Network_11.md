**1. IP 주소와 Interface의 기본 개념**

- **IP address**: 호스트나 라우터 자체가 아닌, 기기의 **Interface**에 할당되는 32-bit identifier
- **Interface**: 호스트나 라우터와 physical link 사이의 연결 지점
    - 라우터는 일반적으로 여러 개의 interface를 가짐
    - 호스트는 보통 1~2개(예: 유선 Ethernet, 무선 WiFi)의 interface를 가짐
    - 호스트 연결 방식: 중간에 라우터를 거치지 않고, 유선 Ethernet interface들은 Ethernet switch로, 무선 WiFi interface들은 WiFi base station으로 직접 연결

**2. Subnets (서브넷)**

- **Subnet의 정의**: 중간에 위치한 라우터(intervening router)를 통과하지 않고도 물리적으로 서로 도달할 수 있는 device interface들의 집합
- **Subnet을 정의하는 방법**: 네트워크 망에서 호스트나 라우터의 각 interface를 물리적으로 분리(detach)했을 때 생성되는 고립된 네트워크 섬("islands") 각각이 하나의 **subnet**
- **IP address의 구조**:
    1. **Subnet part**: 같은 subnet에 속한 device들이 공통으로 가지는 상위 비트
    2. **Host part**: 각 기기를 식별하는 나머지 하위 비트
- **Subnet mask**: IP 주소에서 어디까지가 subnet part인지를 나타냄 (예: `/24`는 32-bit 중 상위 24-bit가 subnet part)

**3. CIDR (Classless InterDomain Routing)**

- 기존의 클래스 기반 주소 할당을 넘어, **Subnet portion**의 길이를 임의의 길이로 지정
- 형식: `a.b.c.d/x` (여기서 `x`는 subnet portion의 비트 수. 예: `200.23.16.0/23`)
- 블록 크기는 2^n 고정
- 그래서 남은 공간은 CIDR로 나눔 ⇒ 2의 제곱 수의 합으로 표현
    - IP 주소 마지막 숫자 ~~.~~.~~.여기! 를 2진수로 바꾸고, 0개수(k) 세어서 2^k크기의 블록으로 할당
    - 해당 블록 첫 주소의 host part가 다 0이어야 함. 그걸 network address로 하기로 했으니까. 그래서 0개수로 블록 크기를 설정하는 것
- network 주소 쓸 때도 당연히 마스크를 함께 표시해야 함

**4. 호스트의 IP 주소 획득: DHCP**

호스트가 IP address를 얻는 방법은 관리자(sysadmin)에 의해 설정 파일에 하드코딩되거나, **DHCP**를 통해 동적으로 얻는 방법

- **DHCP (Dynamic Host Configuration Protocol)**: 호스트가 네트워크에 "조인(joins)"할 때 서버로부터 IP 주소를 동적으로 얻게 해주는 **"plug-and-play"** 프로토콜
    - 클라이언트는 지금 자기 IP 주소도 없고, 자신이 속한 서브넷도 없는 백지상태
    - Network Address (네트워크 주소): 모든 비트가 0인 주소
    - Broadcast Address (브로드캐스트 주소): 모든 비트가 1인 주소
- **주요 특징**: 사용 중인 주소의 lease(임대)를 갱신(renew)할 수 있고, 기기가 연결되어 있을 때만 주소를 점유하므로 address reuse(재사용)가 가능하며, mobile user를 지원
- **DHCP Client-Server Scenario (4단계)**: 전부 broadcast로 진행
    1. **DHCP discover**: 클라이언트가 DHCP server를 찾기 위해 메시지를 전송
    2. **DHCP offer**: 서버가 사용할 수 있는 IP 주소를 제안하며 응답
    3. **DHCP request**: 클라이언트가 제안받은 IP 주소를 사용하겠다고 요청
    4. **DHCP ACK**: 서버가 IP 주소 할당을 최종 확정
    *(※ 클라이언트가 이전에 주소를 할당받아 기억하고 있고, 재사용하길 원하면 앞의 discover, offer 단계는 생략 가능. 그래도 request부터는 해야 함!)*
    
    ![DHCP client-server 시나리오: DHCP discover → offer → request → ACK 4단계 메시지가 클라이언트와 서버 사이에서 broadcast로 오가며, 각 메시지의 src/dest, yiaddr, transaction ID가 표시된 다이어그램](/assets/img/posts/Network_11/image.png)
    
- **DHCP가 추가로 제공하는 정보**: DHCP는 IP address, 클라이언트의 **first-hop router(다른 서브넷으로 향하는 트래픽을 처음으로 받아 라우팅하는 라우터)** 주소, **DNS server**의 이름 및 IP address, 그리고 네트워크의 **subnet mask** 정보까지 함께 반환

**5. 네트워크의 IP 주소 획득과 계층적 라우팅**

네트워크(기관) 단위로도 IP 주소를 획득

- **주소 블록 할당**: 네트워크는 자신들에게 인터넷을 제공하는 상위 provider **ISP**의 address space 중 일부 block을 할당받음
    - Network Address (네트워크 주소): Host part의 모든 비트가 0인 주소
    - Broadcast Address (브로드캐스트 주소): Host part의 모든 비트가 1인 주소
- **Hierarchical addressing (계층적 주소 할당)**: 계층적 주소 체계를 사용하면, ISP는 여러 하위 네트워크의 주소를 하나로 묶어 **Route aggregation**을 수행하여 라우팅 정보를 효율적으로 인터넷에 광고(advertisement)
    
    ![계층적 주소 할당(Route aggregation): 8개 조직(Organization 0~7)의 서브넷을 Fly-By-Night-ISP가 200.23.16.0/20이라는 하나의 더 큰 prefix로 묶어 인터넷에 광고하는 다이어그램](/assets/img/posts/Network_11/image-1.png)
    
- **Longest Prefix Matching (LPM)**: 만약 특정 기관이 다른 ISP로 이동하여 주소 범위에 예외가 생기거나 겹치게(overlapping) 되더라도, 라우터는 **more specific route**(더 구체적이고 길게 일치하는 프리픽스)를 우선적으로 매칭
    
    ![LPM 예시: Organization 1이 ISPs-R-Us로 옮기면서, Fly-By-Night-ISP가 광고하는 200.23.16.0/20과 겹치는 200.23.18.0/23을 ISPs-R-Us가 더 구체적인 prefix로 별도 광고해 라우터가 이를 우선 매칭하는 다이어그램](/assets/img/posts/Network_11/image-2.png)
    
    - 표에서 prefix끼리 겹치는 부분 확인 → 가장 짧은 것부터 순차적으로 이전 것 대비 추가된 부분 표시
    - 주소 계산 tip: $2^n-1 = 2^0 + 2^1 + 2^2 + \ldots + 2^{n-1}$

**6. ICANN과 IP 주소 고갈 문제**

- **ICANN (Internet Corporation for Assigned Names and Numbers)**: 글로벌 IP address 블록을 할당하고, 이후에는 ISP가 계층적으로 할당
- **주소 고갈과 해결책**: 32-bit를 사용하는 IPv4 address 공간은 이미 고갈(exhaustion)
    
    **⇒ NAT (Network Address Translation)**, 궁극적인 해결을 위해 128-bit address space를 가진 **IPv6**가 도입
