### OS: 하드웨어 자원을 독점적으로 관리하는 시스템 SW

1. OS 키워드3
    
    (1) 가상화
    
    - 메모리(부모랑 자식이랑 가상 주소는 동일한데, 물리주소는 다름)
    - CPU: Time sharing(시분할)로 스케줄링 ⇒ 프로세스가 자기만의 CPU가 있는 것처럼 보임
    
    (2) 동시성
    
    - 프로세스: 실행 중인 프로그램, 독립된 메모리
    - 스레드: 한 프로세스 내부에서 메모리를 공유하는 실행 흐름
    
    (3) 영속성
    
    : DRAM 휘발성 → 시스템 영속적 저장
    
2. CPU 기본 구성
    
    (1) ALU: 산술연산, 논리연산
    
    (2) CU: 메모리에서 명령어 fetch, decode, 제어 신호
    
    (3) 레지스터: CPU 내부 초고속 저장 공간, ALU, CU 정보 임시 보관
    
    = CPU ↔ 외부 장치와 Bus 로 연결되어 있음
    
3. 명령어 실행 사이클
    
    (1) fetch: 메모리에서 명령어를 가지고 와서
    
    (2) decode: CU가 해독하고 필요한 연산을 결정
    
    (3) execute: ALU가 연산을 실행하고, 연산 결과를 regs나 mem에 저장
    
    ++ 폰 노이만 구조: 
    
    - CPU, 메모리 간 단일 버스
    - 명령어, 데이터는 동일 메모리
4. 메모리 계층 구조
    
    
    | 레지스터 |
    | --- |
    | 캐시 |
    | 메인 메모리(RAM) |
    | flash disk(SSD) |
    | traditional disk(HDD) |
    | remote secondary storage(cloud) |
5. 커널
    - 정의: 항상 메모리에 상주하며, 하드웨어를 직접 제어하고 시스템 자원을 관리하는 SW
    - 구조
        - monolithic: 모든 OS 서비스를 같은 커널에서 실행
        - microkernel: 최소 핵심 서비스만 커널에서 실행하고, 나머지는 별도의 프로세스
        
        ex. linux: hibrid(monolithic + modular)
        
    - 커널이 따로 존재해야 하는 이유
        
        보호, 안정성, 보안을 위해. ⇒ 따로 분리해서 사용자가 커널을 통해서만 하드웨어에 접근할 수 있게 함
        
        - 안 했을 때의 문제
            - 메모리 덮어쓰기
            - 디스크 포맷
            - CPU 독점
6. 프로세스
    - 프로세스 적재 과정
        
        (1) Code, Data 적재
        
        (2) Stack 할당
        
        (3) Heap 생성
        
        (4) I/O 초기화
        
        (5) 제어를 main()으로 이전
        
    - 상태 전이도

        ```mermaid
        %% 프로세스 5상태 전이도 (The 5-State Process Model)
        graph TD
            %% 노드 정의 및 스타일
            New(생성: New)
            Ready(준비: Ready)
            Run(실행: Running)
            Block(대기: Waiting/Blocked)
            End(종료: Terminated)

            %% 스타일 설정
            classDef state fill:#e1f5fe,stroke:#01579b,stroke-width:2px;
            classDef core fill:#b3e5fc,stroke:#01579b,stroke-width:2px,stroke-dasharray: 5 5;
            class New,Ready,Run,Block,End state;
            class Ready,Run,Block core; %% CPU 할당과 관련된 핵심 상태는 점선 처리

            %% 전이 화살표 정의
            New -->|admitted: 프로세스 생성| Ready
            
            Ready -.->|Dispatch: 스케줄러가 CPU 할당| Run
            Run -.->|Timeout: 할당 시간 초과 - Preemption| Ready
            
            Run -->|I/O or Event Wait: 대기 사유 발생| Block
            Block -->|I/O or Event Completion: 대기 해제| Ready
            
            Run -->|Exit: 프로세스 종료| End
        ```

    - 메모리 구조

        | **Stack** | 지역 변수, 매개변수, 복귀 주소 |
        | --- | --- |
        | ... | ... |
        | **Heap** | 동적 할당 |
        | **Data** | 전역 변수, 정적 변수 |
        | **Code** | 기계어 코드 |
    - BP: 현재 프레임 시작
    - SP: 현재 스택 최상단
