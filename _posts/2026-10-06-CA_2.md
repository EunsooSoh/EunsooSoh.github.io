1. 응답 시간과 처리량
    * 응답 시간: 하나의 작업을 수행하는 데 걸리는 시간
    * 처리량: 단위 시간당 수행되는 총 작업량
    => 성능 평가시 이 두 가지를 모두 고려해야 함


2. **실행 시간**
    * 성능 = 1/(실행시간)으로 정의
    * 측정
        * 경과 시간(=응답시간)
            * 사용자 측면에서 걸린 시간
                = 모든 측면을 포함한 총 응답 시간
            * 시스템 성능을 결정
        * CPU 시간
            * 서버 측면에서 작업을 처리하는 데 소요된 시간
            * 구성
                * 사용자 CPU 시간: 사용자 PGM 내부에서 실행되는 시간
                * 시스템 CPU 시간: PGM이 요청할 때 운영체제 커널이 수행되는 시간
            * 구하는 방법
                * <span class="hl-yellow">알아둬야 할 단위: </span>

                    | 단위 | 기호 | 값 |
                    |---|---|---|
                    | pico sec | ps | $10^{-12}$ 초 |
                    | nano sec | ns | $10^{-9}$ 초 |
                    | sec | s | $1$ 초 |

                $$\text{CPU 시간} = {(\text{CPU 클럭 사이클 수} \times \text{클럭 사이클 시간})}$$
                
                * CPU 클럭: 일정한 주파수의 클럭에 의해 제어되는 디지털 하드웨어의 작동
                * 클럭 주기: 클럭 사이클의 지속 시간(1->0 한 번)
                * 클럭 주파수(속도): 초당 클럭 사이클 수

                $$\text{CPU 시간} = \frac{CPU 클럭 사이클 수}{클럭 속도}$$

                $$\text{CPU 시간} = \text{명령어 수} \times \text{CPI} \times \text{클럭 사이클 시간}$$

                * CPI: Cycle per instuction, 하나의 명령 당 사이클 수
                
                * 가중 평균 CPI: 여러 명령어 클래스가 존재할 때, 상대 빈도를 적용해 계산

                $$\text{평균 CPI} = \sum_{i=1}^{n} \left( \text{CPI}_i \times \frac{\text{명령어 수}_i}{\text{전체 명령어 수}} \right)$$

    * 성능 요약

        1) CPU 성능 방정식

        $$\text{CPU 시간} = \underbrace{\frac{\text{명령어 수}}{\text{프로그램}}}_{\text{① 명령어 수 (IC)}} \times \underbrace{\frac{\text{클럭 사이클 수}}{\text{명령어}}}_{\text{② 평균 CPI}} \times \underbrace{\frac{\text{초 (시간)}}{\text{클럭 사이클}}}_{\text{③ 클럭 사이클 시간 }(T_c)}$$

        2) <span class="hl-yellow">성능에 영향을 미치는 요인 4</span>

        (1) 알고리즘 -> 명령어 수 (IC), CPI   
        (2) 프로그래밍 언어 -> 명령어 수 (IC), CPI      
        (3) 컴파일러 -> 명령어 수 (IC), CPI    
        (4) ISA(명령어 집합 구조) -> 명령어 수 (IC), CPI, **클럭 속도**
    * 실행 시간이 가장 적합한 성능 측정 기준임


3. 전력 장벽과 멀티 코어

    * CMOS IC 동적 전력 공식:

        $$P = \text{부하 용량}(C) \times \text{전압}(V)^2 \times \text{스위칭 빈도}(f_{sw})$$

    * 단일 코어의 제약3: (1) 전력, (2) 명령어 수준 병렬성, (3) 메모리 지연 시간

    * 전력 장벽: 전압을 더 이상 낮추기 어렵고, 발열을 제거하기 힘든 물리적 한계

    => 멀티코어로. (멀티코어: 하나의 침에 둘 이상의 프로세서가 있는 것)


4. 표준 성능 평가 (SPEC 벤치마크)

    * SPEC CPU 벤치마크: 
        * 실제 작업 부하를 대표하는 정수 연산(CINT) 및 부동 소수점 연산(CFP) 프로그램들로 구성
        * 기준 시스템 대비 실행 시간 비율의 기하 평균으로 성능을 정규화
            * 실행 시간의 비 n개 다 곱하고 그 결과를 n제곱근 씌운 것 
    * SPECpower 벤치마크: 서버의 다양한 부하 수준(Target Load 0%~100%)에 따른 전력 소비 효율을 측정(ssj_ops는 부하가 10% 증가될 때마다의 성능)
        * 부하가 0%일 때도 Average Power 0이 아닐 수 있음(기본 전력, 누설 때문에)
        * 전력 소비 효율: $$\text{ssj\_ops}/\text{watt}$$
            * 이 값이 클수록 동일 전력에서 더 많은 작업 처리를 할 수 있다는 뜻

5. 성능 평가의 함정과 오류 

    <span class="hl-yellow"> 1) Amdahl의 법칙 (Amdahl's Law):</span>
    시스템의 일부만 개선했을 때 얻을 수 있는 전체 성능 향상에는 한계가 존재

    $$T_{\text{improved}} = \frac{T_{\text{affected}}}{\text{개선 비율}} + T_{\text{unaffected}}$$

    => <span class="hl-yellow">빈도가 높은 핵심 작업을 최적화해야 함</span>

    2) 유휴 상태 전력: 
    * CPU는 저부하(10~50%) 상태에서도 대량의 전력을 소비
    => 전력 소비가 부하에 비례하도록 프로세서 설계하는 것 고려(=낮은 부하에서는 낮은 전력을 소비하게 설계하자)

    3) MIPS 지표의 함정: 

    $$\text{MIPS} = \frac{\text{명령어 수}}{\text{실행 시간} \times 10^6} = \frac{\text{클럭 속도}}{\text{CPI} \times 10^6}$$ 
    
    => ISA 차이나 명령어 복잡도를 반영X -> 사용X
