**1. Network-layer Functions와 Control Plane의 구조**

네트워크 계층은 크게 두 가지 기능을 수행

- **Forwarding (Data plane):** 라우터의 입력 링크로 들어온 패킷을 적절한 출력 링크로 이동. 이것만 하기 때문에, control plane이 HW든 SW든 data plane의 동작에는 영향을 주지 않는 분리 구조가 성립
- **Routing (Control plane):** 패킷이 source에서 destination까지 가는 전체 경로(route)를 결정

**Control plane**을 구축하는 2가지 접근 방식

1. **Per-router control (Traditional):** 각 라우터 내부에 개별적인 **Routing Algorithm** 컴포넌트가 존재 → 라우터들끼리 상호작용하며 제어 평면을 구성
2. **Logically centralized control (SDN):** 논리적으로 중앙 집중화된 **Remote Controller(SW)**가 경로를 계산 → 각 라우터에 forwarding table을 내려받아 설치(install)

**2. Routing Algorithm의 분류 (Classification)**

라우팅 알고리즘의 목표: 송신 호스트에서 수신 호스트까지 라우터들을 거쳐가는 "good" paths (least-cost paths)를 찾는 것. path: sequence of routers

- **정보의 범위 (Global vs. Decentralized):**
    - **Global:** 모든 라우터가 네트워크의 완벽한 topology(연결방식)와 link cost 정보(complete information)를 가짐
        
        ⇒ **"Link State (LS)"** algorithms
        
    - **Decentralized:** 각 라우터는 처음에 직접 연결된 이웃(attached neighbors)의 link cost만 알며, 이웃과 정보를 교환하면서 반복적으로(iterative) 경로를 계산
        
        ⇒ **"Distance Vector (DV)"** algorithms
        
- **변화 속도 (Static vs. Dynamic):**
    - **Dynamic:** 주기적으로(periodic updates) 혹은 link cost 변화에 즉각적으로 반응하여 경로가 빠르게 변함. **LS** algorithms
    - **Static:** 경로가 시간이 지남에 따라 매우 천천히 변함. **DV** algorithms

**3. Link State (LS) Algorithm: Dijkstra's Algorithm**

모든 노드가 "link state **broadcast**"를 통해 동일한 전체 네트워크 정보를 갖추고(Centralized), 한 노드에서 다른 모든 노드까지의 최소 비용 경로를 계산하는 알고리즘

- **주요 Notation (표기법):**
    - $c_{x,y}$: node x에서 y까지의 **direct link cost** (직접 연결되지 않았다면 $\infty$)
    - $D(v)$: source에서 destination v까지의 현재 최소 비용 추정치
    - $p(v)$: source에서 v로 가는 경로 상의 직전 노드
    - $N'$: 최소 비용 경로가 확실히 결정된 노드들의 집합
- **동작 원리:** 아직 $N'$에 속하지 않은 노드 중 $D(v)$가 최소인 노드 $w$를 찾아 $N'$에 추가하고, $w$의 이웃 노드들의 $D(v)$를 업데이트
$D(v) = \min(D(v), D(w) + c_{w,v})$
- **Algorithm complexity (복잡도):** $n$개의 노드가 있을 때 $O(n^2)$의 복잡도를 가지며 (효율적 구현 시 $O(n \log n)$), 각 라우터의 메시지가 네트워크 전체로 broadcast되어야 하므로 **message complexity**도 $O(n^2)$
    
    ![다익스트라 알고리즘 의사코드: N'을 {u}로 초기화한 뒤, 인접 노드는 direct link cost, 나머지는 무한대로 D(v)를 설정하고, N'에 없는 노드 중 D(w)가 최소인 w를 찾아 N'에 추가하며 이웃의 D(v)를 갱신하는 반복 절차](/assets/img/posts/Network_14/image.png)
    
- **문제점:** Link cost가 트래픽 볼륨(traffic volume)에 의존적으로 변할 경우, 경로가 양쪽으로 번갈아 쏠리며 계속 바뀌는 **route oscillations** 현상이 발생
    
    = 트래픽이 경로를 결정하는데, 그 경로 결정이 또 트래픽에 영향을 줌
    

- 현재 선택한 것 표시 → 그것과 표시 안 한 것으로 가는 경로 비용만 갱신할지 말지 확인
    
    → 갱신은 그곳까지 가는 비용(표에서) + 거기서 목적지까지 가는 비용(그래프에서)

**4. Distance Vector (DV) Algorithm: Bellman-Ford**

이웃 노드들끼리만 정보를 교환하며 동작하는 알고리즘

- **Bellman-Ford equation:** $D_x(y) = \min_v \{ c_{x,v} + D_v(y) \}$
*(x에서 y로 가는 최소 비용 ＝ x의 모든 이웃 v들에 대해 x에서 그 이웃 v로 가는 직접 비용 + v에서 y로 가는 총 비용 중 최솟값)*
    
    ![Bellman-Ford 방정식: D_x(y) = v가 N(x)에 속할 때 c(x,v) + D_v(y)의 최솟값으로 정의되는 수식](/assets/img/posts/Network_14/image-1.jpeg)
    
    N은 이웃. 자기 자신은 포함하지 않음
    
- **동작 방식 (1→2→3→1→2…):**
    1. **Wait:** Local link cost가 변하거나 이웃으로부터 **DV update message**를 받을 때까지 대기
    2. **Recompute:** 알림을 받으면 Bellman-Ford 공식을 사용하여 자신의 **DV estimate**를 계산
    3. **Notify:** 만약 재계산 결과 자신의 목적지 DV가 하나라도 변경되었다면, 이웃들에게 새로운 DV를 알림 (변화가 없으면 아무 행동도 하지 않음: **self-stopping, asynchronous**)
- **Link cost changes에 대한 반응:**
    - 정보 전달에 걸리는 시간이 떨어진 hop수만큼 걸림
        
        ![DV 알고리즘의 정보 전파 속도: c의 상태 변화가 t=0부터 시작해 t=1엔 b, t=2엔 a·e, t=3엔 d·f·h, t=4엔 g·i까지 hop 수만큼 순차적으로 전파되는 토폴로지와 타임라인](/assets/img/posts/Network_14/image-2.png)
        
    - **"Good news travels fast":** 링크 비용이 감소하는 등 좋은 소식은 네트워크 전체로 빠르게 전파
    - **"Bad news travels slow":** 링크 비용이 크게 증가하거나 끊어지는 나쁜 소식은, 노드들이 서로의 잘못된(과거의) 최소 비용 정보를 참조하며 천천히 비용을 무한히 증가시키는 **Count-to-infinity problem**(라우팅 루프)을 발생시킴

**5. LS와 DV Algorithms의 비교 (Comparison)**

두 알고리즘의 주요 차이점

- **Message complexity:**
    - **LS:** $O(n^2)$ 메시지가 전체 네트워크에 보내짐
    - **DV:** 이웃끼리만 교환하므로 수렴 시간(convergence time)에 따라 메시지 양이 다름
- **Speed of convergence (수렴 속도):**
    - **LS:** $O(n^2)$ 알고리즘이며, oscillations 문제 존재
    - **DV:** 수렴 속도가 다양하며, routing loops와 **count-to-infinity problem** 존재
- **Robustness (라우터 오작동 또는 해킹 발생 시):**
    - **LS:** 라우터가 자신의 **incorrect link cost**만 주변에 광고. 계산은 각 라우터가 독자적으로 하므로 피해가 국소적
    - **DV:** 라우터가 목적지까지의 전체 경로 비용을 잘못 광고. 예컨대 "내가 모든 곳으로 가는 최저 비용 경로를 안다"고 속여 트래픽을 흡수하는 **Black-holing**이 가능. 이웃이 그 정보를 그대로 가져다 쓰기 때문에, 오류가 네트워크 전체로 전파됨
