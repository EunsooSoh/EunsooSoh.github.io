### 3.2 Managing address mapping information
* FTL 구현 시, 매핑 정보를 저장하는 방식(scheme)을 고려해야 함
* power-on 과정에서 매핑 테이블을 재구성할 수 있으려면, sudden power-off event에도 매핑 정보가 유실되지 않도록 flash memory 어딘가에 영구적으로 보관되어야 함
* 매핑 정보 저장 기법은 두 가지로 분류됨: map block method, per block method

#### 3.2.1 Map block method
* map block: 매핑 정보를 저장하는 flash memory의 전용 block
* block mapping의 경우 매핑 정보 전체를 block 하나로도 충분히 담을 수 있지만, 대부분의 FTL 구현은 여러 개의 map block을 둠
    * map block을 1개만 쓰면 -> 그 block에 erase가 매우 빈번하게 발생
    * -> 여러 map block을 써서 잦은 erase 완화

![Fig. 6 map block 동작](/assets/img/posts/FTL_3/image.png)
* 매핑 정보(logical block number, physical block number쌍)는 최신 map block의 비어있는 sector 하나에 기록됨
    * 최신 map block: 여러 map block들을 시간순으로 번갈아 채워나가는데, 그중 지금 기록이 이루어지고 있는(또는 가장 최근 기록이 담긴) map block
* physical block number들은 logical block number 순서대로 그 sector 안에 저장됨
* 만약 sector 하나로 모든 physical block number를 다 담을 수 없으면 -> 2개 이상의 sector 사용

* mapping table 갱신 과정
    * file system의 write로 인해 매핑 정보가 바뀌면 -> 위의 recording 작업 수행
        * recoring: 사용자가 요청한 데이터 자체를 쓰는 write로 인해 바뀐 "매핑 테이블 갱신 내용"을 flash에 저장(영구 저장)
    * 기록할 때 map block pool에 비어있는 sector가 없으면 -> erase 연산을 실행해서 map block을 확보해야 함
    * 매핑 테이블은 RAM에 캐시해서 빠른 lookup 가능
    * power-on 시 복구: RAM의 매핑 테이블은 전원이 꺼지면 사라지므로, 최신 map block의 가장 최신 sector를 flash에서 읽어서 RAM에 매핑 테이블을 재구성함
        * -> 정보가 한 곳(map block pool)에 몰려있어서, 최신 위치 하나만 읽으면 복구 가능

#### 3.2.2 Per block method
* 매핑 정보를 flash memory의 **각 physical block마다** 나눠서 저장
* map block 방식과 달리 logical block number(lbn)가 각 physical block의 첫 번째 page의 spare area에 저장됨
* 추가로, lsn을 physical block 내 sector에 매핑하려면 -> **logical sector number(lsn)**가 그 block의 각 sector에 개별적으로 기록됨
    * 3.1.3절 hybrid mapping에서 이미 확인한 "spare area에 lsn 기록" 방식과 동일한 메커니즘
* power-off recovery: lbn과 lsn **둘 다** spare area에서 읽어서 사용
    * -> 정보가 각 block에 흩어져 있어서, 관련된 모든 physical block들을 각각 뒤져봐야 복구 가능

![Fig 7. Per block 동작](/assets/img/posts/FTL_3/image-2.png)
* logical block number 3 -> physical block number 0
* logical block number 2 -> physical block number 1
* (이하 동일한 방식)

### 3.3 RAM table
* RAM 크기는 FTL 알고리즘 설계에서 매우 중요함 -> 전체 시스템 비용을 좌우하는 핵심 요소
    * RAM↓ -> 시스템 비용↓(RAM 자체가 비용임)
    * 단, RAM이 충분하면 -> 성능↑ (트레이드오프)
* FTL 알고리즘마다 고유한 RAM 구조를 가지며, 이 **RAM 구조에 따라 FTL 알고리즘을 분류**할 수 있음
* RAM은 다음 세 가지 정보를 저장하는 데 쓰임:
    1. **Logical-to-physical mapping 정보**: RAM의 주된 용도. RAM에 접근함으로써 read/write할 physical flash 위치를 효율적으로 찾을 수 있음
    2. **Free memory space 정보**: flash memory의 빈 공간 정보를 RAM에 저장해두면, FTL이 **추가 flash memory 접근 없이** 메모리 공간을 관리할 수 있음
    3. **Wear-leveling 정보**: 예를 들어, block별 erase count(지워진 횟수)를 RAM에 저장

* 1:2 RAM table 예시
![1:2 RAM table 예시](/assets/img/posts/FTL_3/image-3.png){: width="700" height="498" }
* 가정: 1 physical block = 16 sector, **1:2 block mapping** 사용 (하나의 logical block이 최대 2개의 physical block에 매핑 가능)
* 테이블 구성 요소:
    * **PBN1, PBN2**: 첫 번째/두 번째 physical block 주소
    * logical block 00 -> physical block 00, 10에 매핑됨 (2개)
    * 오른쪽 sector 정보: 실제 valid data가 저장된 위치 표시
        * 0: PBN1에
        * 1: PBN2에
        * ex. logical block 00의 sector 0 -> physical block **10**의 sector 0에 저장됨
* **플래그(flag)들**:
    * **Move flag**: 한 block의 일부 sector들이 다른 block에 저장되어 있음을 표시
        * 0이면 이 logical block의 모든 sector가 전부 원래 자리인 PBN1에 있음
    * **Used flag**: 해당 block이 현재 사용 중임을 표시
    * **Old flag**: 해당 block의 데이터가 더 이상 유효하지 않음을 표시
    * **Defect flag**: 해당 block이 불량(bad) block임을 표시
